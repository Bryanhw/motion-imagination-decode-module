# 真采校准上机速查命令卡（A 方案：真采 → 模型 → 在线解码 → 游戏）

> 用途：新设备到位并书面确认参数后，照本卡一次性跑通「真采数据 → 专属模型 → 在线解码 → 游戏被驱动」闭环。
> 依据：`docs/TechDesign-BCI-Decoder-MVP.md`、`docs/MVP规格说明书.md`、`docs/calibration_flow.md`、
> `docs/D1_至D2_模型数据格式交接_20261117.md`、`docs/阎浩文M4_设备通道诊断与三方案定夺_20261117.md`。
> 所有命令在 **`bci-decoder/`** 目录下执行；Shell 为 **Windows PowerShell 5.1**，**禁止使用 `&&`**（用 `;` 或分步执行）。

---

## 0. 开工前提（先对表，不满足别往下走）

| 检查项 | 要求 | 出处/说明 |
|---|---|---|
| RA2 设备参数书面确认 | 型号、**8 通道顺序 = 冻结契约 `C3, Cz, C4, CP3, CP4, P3, P4, Oz`**、采样率、LSL 流名 | 组长/PM 责任，时限 2026-11-17 已过仍待回填；**通道顺序即语义（红线 4），绝不重排** |
| 位点适用性 | 设备电极必须能落到上述 8 个 MI 位点才能走本卡 | 现有 XMuse S Athena 实测位点 = `TP9/AF7/AF8/TP10`（前额+耳后），**不符合** MI-BCI 契约，用它硬做只会长期出 `idle`（红线 1 的正确行为）——见 M4 设备诊断文档，位点不对则本卡不适用，维持公开数据回放方案 |
| 数据契约 | `raw.npy` 形状 `(n_ch, n_t)`、µV 单位；`labels.npy` 一维、每 trial 一类、取值 ∈ `{left,right}` 或索引 `0/1` | 红线 4：通道顺序与 `source.ch_names` 一致 |
| 环境 | 激活 `bci-decoder\.venv`（Python 3.14.7，scikit-learn/websockets 已装） | **勿用全局 Python**；临时产物不写仓库根 |

## 1. 数据文件化与预检（进 calibrate 前**必跑**）

设备导出/转写为两个 `.npy` 后，先跑预检脚本核对格式并推断采样率（防 calibrate 静默切错 trial）：

```powershell
.venv\Scripts\python.exe scripts\precheck_real_data.py `
  --real-data data\raw.npy --labels data\labels.npy `
  --config configs\default.yaml --trial-seconds 2.0 `
  --subject-id alice --out-dir .deepworks\tmp\precheck_alice
```

- 退出码：`0`=PASS（可进 calibrate）｜`1`=WARN（可继续但核对）｜`2`=FAIL（校准必失败，先修数据）。
- 重点看两处：**推断采样率 ≠ 配置 sfreq**（如设备 256Hz vs 配置 250Hz，会错位，需改 `configs/default.yaml` 的 `source.sfreq` 或核对设备）；**labels 只有 1 类**（做不了二分类）。
- 通道数不符会直接 FAIL：期望 8 通道 = 冻结契约，raw 通道数/顺序必须一致。

## 2. 专属模型训练（calibrate.py 真采分支）

```powershell
.venv\Scripts\python.exe scripts\calibrate.py `
  --subject-id alice `
  --real-data data\raw.npy --labels data\labels.npy `
  --config configs\default.yaml `
  --trial-seconds 2.0 `
  --out-dir .deepworks\tmp\calib_alice
```

- `--trial-seconds`：默认 2.0（= 滑窗 2.0s）。**真采时以预检确认的每 trial 时长为准**（公开数据 22ch 回放时必须 4.004，见交接文档；真采按设备实际范式）。
- 产物四件套：`classifier.joblib`（LDA）、`csp.joblib`（CSP）、`online.yaml`（可直接被 `cli run` 加载）、`metadata.json`（来源/规模，不含准确率）。
- **已知坑（WinError 5）**：默认 `--out-dir artifacts\users` 会被系统拦 Python 写入。先写 `.deepworks\tmp\`，再用 PowerShell 移入正式目录：

```powershell
New-Item -ItemType Directory -Force -Path artifacts\users\alice | Out-Null
Move-Item .deepworks\tmp\calib_alice\alice\* artifacts\users\alice\
```

## 3. 在线解码冒烟（sink=console → websocket）

```powershell
# 3.1 先看生效配置
.venv\Scripts\python.exe -m bci_decoder.cli show-config --config artifacts\users\alice\online.yaml

# 3.2 console 冒烟（确认不报错、有决策输出；--chunks 限窗口防太长）
.venv\Scripts\python.exe -m bci_decoder.cli run --config artifacts\users\alice\online.yaml --chunks 200

# 3.3 切 WebSocket 输出（冻结端口 8765）
.venv\Scripts\python.exe -m bci_decoder.cli run --config artifacts\users\alice\online.yaml --outputs websocket
```

- 确认逐行 JSON 消息（9 冻结字段：`t_data/t_wall/label/label_id/confidence/probs/state/compute_ms/window_seconds`），`label_id == -1` 当且仅当 `label == "idle"`。
- 未训练 / 模型缺失 / 置信度不足 → 必须输出 `idle`（红线 1），绝不给游戏发随机左右指令。

## 4. 游戏接线（新增终端 2，连接解码器 WS 8765）

```powershell
.venv\Scripts\python.exe -m game.platformer.main --mode ws --ws-url ws://127.0.0.1:8765
```

- 解码器终端（3.3）保持运行；HUD 显示输入源=WS；连接丢失自动每 0.5s 重连，1.5s 无新消息回安全态 `NONE`。
- 键盘兜底仅作工程自检；演示画面**如实标注**，绝不冒充脑控。

## 5. 红线（照此自查，逐条打勾）

1. 未训练/模型缺失/置信不足 → 只输出 `idle`（红线 1）。
2. 在线链路只用**因果滤波**（`sosfilt` + 跨 chunk 保持状态），**禁止** `filtfilt`（红线 2）。
3. 输出消息字段不增删；`label_id == -1` ↔ `label == "idle"`（红线 3）。
4. 通道顺序 = 语义：`C3, Cz, C4, CP3, CP4, P3, P4, Oz`，绝不重排（红线 4）。
5. 滑窗 2.0 s、步长 0.5 s、2 类 + `idle`，不擅改（红线 7 / 契约）。
6. 真人原始数据不入库；新证据按 X10 模板记录「谁跑的/输入/命令/产出」。
7. 只报 **Kappa**，不报裸准确率；免校准与校准后数字须同一测试集同一算法口径。
8. 演示录屏标注「本设备真实采集」；若走公开数据回放则必须标「公开数据集回放 · BCI IV 2a / EEGMMIDB」，不得混淆（红线 1 演示口径）。
