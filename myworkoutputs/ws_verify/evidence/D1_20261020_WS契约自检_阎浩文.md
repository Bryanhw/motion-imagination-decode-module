# WS 契约自检（不依赖游戏的黑盒链路自证）

> 日期：2026-10-20（D1）· 作者：阎浩文 · 配套脚本：`.tools/verify_ws_contract.py`（Git 提交物候选）
> 结论：✅ 16/16 消息全部通过冻结契约校验（字段完整性、安全语义、时序单调）

## 1. 目的

游戏还没做完，但**解码端→WS 的消息流契约可以先被证明是稳定的**：
任何消费端（新像素游戏/弹球/巡检脚本）订阅 `ws://127.0.0.1:8765` 拿到的都是同一份经过验证的消息。
本自检是**纯客户端黑盒**：不碰解码器内部、不做任何准确率评估，只验“消息长得对不对、安不安全”。

## 2. 脚本能力 `verify_ws_contract.py`

- 连接重试：`--connect-timeout` 秒（默认 25）内轮询直到解码端 ws 就绪（解码器启动比客户端慢时用）。
- 逐条校验 9 个冻结字段必须**恰等于** `{t_data, t_wall, label, label_id, confidence, probs, state, compute_ms, window_seconds}`；
- 安全语义：`label ∈ {left,right,idle}`；`label_id == -1 ⟺ label=="idle"`；非 idle 时 `label_id∈{0,1}`；
- 数值域：`0 ≤ confidence ≤ 1`；`probs` 长度 2、归一（误差 ≤0.02）；`state∈{running,stabilizing,error}`；`compute_ms ≥ 0`；`window_seconds == 2.0`（冻结）；
- 时序：`t_wall` / `t_data` 单调不减（不回退）；
- 可选 `--require-idle-only`（用于 nomodel/weak 等“应恒 idle”的配置，检测是否悄悄发了 left/right）。

## 3. 复现步骤（Windows PowerShell，cwd = `bci-decoder/`）

```powershell
# 1) 准备临时 ws 配置：demo_replay_switch.yaml 副本，output.sinks 改为 [console, websocket]，realtime: true
#    （⚠️ 不要给 cmd run 传 --chunks：cmd_run 会强制 realtime=false，解码器毫秒级跑完退出，客户端必然连不上）

# 2) 起解码器（realtime 按 0.5s 真实节奏发，60s 样本）——单独终端
.venv\Scripts\python.exe -m bci_decoder.cli run --config configs\_ws_verify_tmp.yaml

# 3) 另开终端跑自检
.venv\Scripts\python.exe ..\.tools\verify_ws_contract.py --uri ws://127.0.0.1:8765 --n 16
```

## 4. 实测结果（2026-10-20 D1）

- 解码端：realtime 跑满 60s 样本，共 **120 条**决策（left/right/idle 交替出现，见规律切换样本）；
- 自检端：**校验 16 条，失败 0 条**，exit 0；
- 抽样命中：消息含 `label="idle"` 与 `label="left"/"right"` 的条目均通过 `label_id` 一致性校验（idle→-1）。
