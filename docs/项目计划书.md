## 1. 我们要做什么

### 1.1 用人话解释这个项目

想象你要玩一个打砖块游戏，但**不用手**，而是**用脑子想**：

- 你**想象自己的左手在动** → 挡板往左移；
- 你**想象自己的右手在动** → 挡板往右移；
- 你**什么都不想** → 挡板不动。

我们做的事，就是把这三件事变成游戏能听懂的命令。**团队交付的核心就是中间那一层"翻译"。**

### 1.2 一个关键前提：手不动，脑电波也会变

这是整个项目成立的基础，也是初学者最容易误解的一点：

> 就算你的手完全不动，**只要你在"想象"动它**，大脑运动区的电波强弱就会发生变化。
> 我们戴的脑电帽能测到这个变化，从而"猜"出你在想哪只手。

这个能力是可以练的，练几次就会越来越准。

### 1.3 系统分三块，我们只负责中间一块

```
①  脑电帽             ②  解码模块（我们的核心交付物）        ③  游戏
采集脑电波   ──►   把脑电波翻译成"左/右/不动"   ──►   收到指令，让角色动
（企业/设备方负责）       （我们负责）                （游戏团队负责）
```

对我们来说，**最终交付的"产品"其实就是一句话**：

```
"我判断出来了：他在想象左手，可信度 83%"
```

游戏收到这句话就知道该干什么。**能不能驱动游戏，是衡量我们成败的唯一标准。**

## 2. 我们怎么做（简单版）

### 2.1 数据怎么流动

```
脑电帽
  │  蓝牙 / 数据线，每秒送 250 个数
  ▼
【1】等够 2 秒的数据  ← 这一步决定了游戏的"反应速度"
  │
  ▼
【2】洗数据：滤掉干扰（市电嗡声、眨眼、咬牙、身体晃动）
  │
  ▼
【3】找特征：看左右脑"μ 波"（8–13 次/秒的电波）谁更强
  │
  ▼
【4】下判断：用一个小型判别程序算出 左 / 右 / 不动
  │
  ▼
【5】防抖动：连续 3 次都说是"左"才真的输出"左"（避免乱跳）
  │
  ▼
输出一句话给游戏，例如：{"判断":"左", "可信度":0.83}
```

### 2.2 三个"降低难度"的选择（重要）

因为团队没有基础，我们**刻意选了最简单的技术**，不是最先进的：

| 选择 | 我们怎么做 | 为什么不选更高级的 |
|---|---|---|
| 只做 **2 个动作 + 不动** | 左手 / 右手 / 不动 | 4 个动作准确率撑不住 |
| 用**传统方法**，不用深度学习 | 频带功率 + LDA（一种经典小分类器） | 深度学习要好几百人份的数据，我们拿不到；而且它在换人测试时经常还不如传统方法 |
| 把节奏**放慢** | 决策窗口 2 秒 | 运动想象本来就慢，硬追"实时"只会又慢又错 |

### 2.3 一个必须让企业知道的事实：反应慢，不怪算法

运动想象这个方式，从"开始想象"到"游戏响应"大约要 **2 秒**。这 2 秒会花在哪里？

| 花在哪 | 预计耗时 | 占比 |
|---|---|---|
| **等数据攒够 2 秒** | 2000 毫秒 | **99.9%** |
| 电脑实际计算 | 约 2 毫秒 | 0.1% |

> 上表是**开工前的估算**（依据：计算量级已由 `bci-decoder/`（本团队链路）在合成数据上验证，见第 3 节）。真实设备 / 回放数据上我们会用 `cli benchmark` 实测并如实报告。

**结论（这是沟通时最有说服力的一句话）**：

> 慢的原因是"要攒够 2 秒的数据才能判断"，**不是电脑算得慢**。
> 所以把算法换成深度学习、或者买更好的显卡，**对速度几乎没有帮助**。
> 唯一真正能提速的办法是**缩短等数据的窗口**——但窗口越短，信息越少，准确率越低。

**因此：游戏必须配合这个节奏，不能要求它"跟手"。**
打砖块、迷宫、回合制这类游戏合适；射击、格斗这类需要瞬间反应的游戏，**运动想象根本做不到**，请不要提这种需求。

## 6. 怎么算做成了

### 6.1 技术指标

| 指标 | 目标 | 说明 |
|---|---|---|
| 判断准确率 | Kappa > 0.3 | **Kappa** 是扣除"瞎猜也能蒙对"之后的真实水平。0.3 是及格线，0.6 以上算好 |
| 响应时间 | ≤ 3 秒 | 其中 2 秒是在等数据，必须实测并如实报告 |
| 单次计算耗时 | < 50 毫秒 | 计算很快，现有自检同量级约 2 毫秒（须在真实数据上实测） |
| 误触发 | 什么都不想时不能乱动 | 靠"置信度不够就输出不动"来保证 |
| 稳定性 | 连续跑 1 小时不崩、内存不涨 | 长跑脚本验证 |

### 6.2 体验指标（同样重要）

准确率不是唯一标准。还要看：同学玩的时候**有没有"我在控制它"的感觉**、累不累、愿不愿意再玩。每次试玩后填一份 5–8 题的简版问卷。

## 附录：接口长什么样（给游戏同学看）

**解码模块发给游戏的消息**（每秒 / 每 0.5 秒一条）：

```json
{
  "t_data": 12.345,          // 这段脑电的时间点
  "label": "left",           // 判断结果：left / right / idle（不动）
  "confidence": 0.83,        // 可信度，0–1
  "probs": [0.83, 0.17],     // 左、右各自的概率
  "state": "running",        // running=正常；stabilizing=还在稳定中
  "compute_ms": 1.2,         // 这次算了多久
  "window_seconds": 2.0      // 用了多长的数据
}
```

**游戏可以这样用**：

- 直接看 `label` 决定角色动作；
- 用 `confidence` 决定动作力度（可信度高就动得快）；
- `state` 是 `stabilizing` 时动作放缓，避免抖动。

**游戏发给解码模块的控制消息**：

```json
{"cmd": "start"}                        // 开始解码
{"cmd": "stop"}                         // 暂停
{"cmd": "calibrate", "seconds": 120}    // 进入校准
{"cmd": "load_subject", "id": "sub01"}  // 切换到某个同学的模型
```
