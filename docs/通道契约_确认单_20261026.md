# 通道契约确认单 + 无确认情况下的接入方案

> 适用：企业侧暂未提供**设备型号 / 通道顺序 / LSL 流名**三项书面确认，而里程碑④（LSL 实时接入）需要开工。
> 结论先说：**这三项不再构成开工阻塞**。流名用自动发现，通道顺序用显式映射 + 数据自证，缺通道直接报错而不是静默错位。
> 论文/交付口径仍是：**未完成企业核签前，真实设备结论一律标注"通道顺序为数据自证，待企业确认"**。

---

## 一、为什么这三项不能"先跑起来再说"

| 项 | 拿不到会怎样 | 严重度 |
|---|---|---|
| 通道顺序 | 顺序错 → **左右输出稳定相反**，且置信度正常、日志无异常，肉眼全程看不出来 | 🔴 红线 4 |
| 设备型号 | 采样率、工频（50/60 Hz）、通道数、参考方式都不同，滤波与滑窗按错误参数跑 | 🟠 |
| LSL 流名 | 连不上，或连到别的流（比如同时有 EEG 和 marker 流） | 🟡 显式失败，可容忍 |

所以真正的风险只有一条：**通道顺序错了但系统照常输出**。

---

## 二、解法：把"等人确认"换成"现场可判定"

### 2.1 代码层（已完成，`bci-decoder/`）

| 能力 | 位置 | 行为 |
|---|---|---|
| 流自动发现 | `bci_decoder/sources/lsl.py` | `stream_name` 留空 → 按 `stream_type=EEG` 发现；名字没命中会自动回退并打印候选清单 |
| 通道映射 | 同上 `resolve_index_map()` | 优先级 `channel_index` > `channel_map`（设备名→目标名）> 同名匹配 |
| 显式失败 | 同上 | 缺通道/数量不符/无法确定顺序 → `RuntimeError` + 打印设备实际通道清单 + 修法；**绝不补零、绝不按位硬塞** |
| 留痕 | `LSLSource.info_line` | 启动时打印 `stream / sfreq / device_ch / labels / map_by / idx`，可直接进证据 |
| 配置模板 | `configs/lsl_template.yaml` | 三种映射方式都有注释示例 |
| 现场自检 | `scripts/lsl_selftest.py` | `--list` 列流、`--check 60` 抓数据判读、`--emit-config` 生成配置片段 |
| 回归测试 | `tests/test_lsl_mapping.py` | 14 个用例覆盖映射/缺通道/越界/重复/无通道名/大小写 |

`pytest` 全量 **45/45 通过**（原 31 + 新 14）。

### 2.2 现场流程（约 3 分钟，设备一到就能做）

```powershell
cd D:\校企合作项目\bci-decoder
pip install pylsl

# 1) 有哪条流
python scripts\lsl_selftest.py --list

# 2) 抓 60 秒静息，判通道顺序
python scripts\lsl_selftest.py --check 60 --stream-type EEG

# 3) 按判读结果补映射，生成配置片段
python scripts\lsl_selftest.py --check 60 --emit-config
```

判读逻辑（只用静息数据，不需要受试者做任务）：

1. **枕区 alpha**：8–13 Hz 相对功率最强的前 3 个通道里，应至少有一个落在 {Oz, P3, P4}（闭眼更明显）。
2. **几何一致性**：相邻电极相关（C3-CP3、C4-CP4、P3-Oz、P4-Oz）应**高于**对侧远距（C3-P4、C4-P3）。
3. **左右对称**：静息时 C3 / C4 的 mu 功率比应 ≤ 3，超出提示接触不良或位置异常。

输出结论三级：

| 结论 | 含义 | 处置 |
|---|---|---|
| `PASS` | 顺序可信 | 直接接配置跑 |
| `WARN` | 可疑（如 alpha 最强不在枕区） | 睁眼/闭眼复测；仍可疑则用 `channel_index` 试两种顺序对比 |
| `FAIL` | 明显错位（几何一致性反了） | 100% 映射错误，按设备通道表现场重排 |

> 限制：自检能可靠排除"整段错位/左右互换"，但**不能替代功能确认**。最终确证仍建议一次 10 分钟任务（睁眼-闭眼 + 左手/右手握拳各 20 次），看 alpha 抑制与 mu 对侧抑制是否落在预期通道。

### 2.3 文档/流程层

- 配置模板 + 本单，让"设备到了"变成一条可执行 checklist，而不是又一次等回复。
- 证据里注明：`通道顺序 = 数据自证（lsl_selftest 报告）+ 待企业核签`，不夸大。

## 三、给企业的一页确认单（微信回一句话即可）

> 不必签字盖章，勾选或直接回复编号即可。**不回复也不影响我们开工**，我们按数据自证先跑，后续再用这份单子核对。

**1. 设备型号**
- [ ] A. 具体型号：____________（厂商 + 型号）
- [ ] B. 暂不确定 → 我们用 LSL 流里广播的参数（采样率/通道数）

**2. 通道顺序**（从第 1 通道到第 8 通道依次是什么）
- [ ] A. 就是标准 10-20 名称顺序：`C3, Cz, C4, CP3, CP4, P3, P4, Oz`
- [ ] B. 设备通道名不同，名称是：____________（我们写别名表）
- [ ] C. 设备不发布通道名，8 个目标通道在设备上的序号是：____________
- [ ] D. 不清楚 → 我们用 60 秒静息数据自检，出报告后请你们核对一眼

**3. LSL 流名 / 类型**
- [ ] A. 流名：____________，类型：____________
- [ ] B. 不清楚 → 我们自动发现（`stream_type=EEG`），首次连接时把发现的流名回填配置

**回执方式**：微信回复如 `1A / 2A / 3B(流名 MyEEG)` 即可。

## 四、默认假设与风险登记

| 假设 | 依据 | 若假设错误的后果 | 兜底 |
|---|---|---|---|
| 设备通道名是标准 10-20 命名 | 主流设备（Neuracle/OpenBCI/g.tec）默认如此 | 启动即报"找不到目标通道"并打印实际名称 | 填 `channel_map` |
| 采样率 250 Hz | 项目全部离线证据基于 250 Hz | 采样率会被设备实际值覆盖；但滤波器/滑窗按实际 sfreq 重算，所以只是"预期外"不是"错" | 已在 `start()` 覆盖 sfreq |
| 工频 50 Hz | 国内环境 | 若设备在 60 Hz 环境，50 Hz 陷波无效 | `notch_freq: 60` 一行改 |
| 8 个目标通道设备都有 | 项目契约固定 8 通道 | 缺通道直接报错 | 换通道子集或改契约（需组长拍板） |

## 五、如果到 10/30 仍拿不到（降级路径）

1. **不影响 M2 / A8**：A8 演示用合成源，与设备无关。
2. **里程碑④ 改为"设备到场即接"**：把不确定性从"工期"转成"现场 checklist"（本文 §2.2，3 分钟）。
3. **证据口径**：④ 的验收证据写成"通道映射自检报告 + 企业核签单（可后补）"，评审时说明这是**主动的工程防御**，不是遗漏。
4. **不做的事**：不在未确认顺序的情况下对外声称"真实设备解码准确率"（红线 6 同样适用）。
