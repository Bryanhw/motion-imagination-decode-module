## 1. 怎么读这个优先级和难度

### 1.1 优先级定义（按"不学就交不出什么"来定）

| 等级 | 含义 | 判据 | 对应节点 |
|---|---|---|---|
| **P0 · 卡点** | **不学完，任务直接做不动** | 缺了它，MVP 5 项功能（F1–F5）有一项完全无法开工 | 10/27 · W9 |
| **P1 · 提速** | 不学也能跑，但**做不对、说不清、数字不可信** | 缺了它，能让东西"跑起来"，但拿不出可信的准确率与解释 | 11/10 · W11 |
| **P2 · 加分** | 到点再学，**提前学纯属浪费** | 缺了它，前期毫无影响；只在特定里程碑前必须补上 | 12/01–12/15 |

### 1.2 难度定义（用"你会卡在哪"来衡量，不是用"听起来高不高级"）

| 难度 | 含义 | 典型卡点 | 参考学时 |
|---|---|---|---|
| **⭐ 入门** | 有教程就能照着做完 | 环境、语法、API 名字记不住 | ≤ 12 h |
| **⭐⭐ 进阶** | 需要理解**概念**才能用对，照抄必错 | 数组维度对不上、`fit/transform` 顺序错、交叉验证泄漏 | 12–25 h |
| **⭐⭐⭐ 硬** | 需要**数学 + 工程直觉**，网上没有"三行代码答案" | 因果滤波相位延迟、谱估计分辨率权衡、协方差估计与正则化 | ≥ 25 h |

> ⚠️ **难度的最大陷阱**：`sklearn` 和 `mne` 都是 ⭐⭐ 起步——
> 它们的 API 一查就会（看起来 ⭐），但**用错方式调用不会报错，只会给你一个漂亮的错误数字**（实际是 ⭐⭐⭐ 的坑）。
> **典型例子**：先对全体数据做标准化再切分训练/测试 → 数据泄漏 → Kappa 虚高 → 中期评审数字不可信。

### 1.3 优先级 × 难度四象限（先看这张）

| | **⭐ / ⭐⭐ 容易** | **⭐⭐⭐ 难** |
|---|---|---|
| **P0 不学做不动** | ✅ **第一周全力清掉**：Python、Git、NumPy、Matplotlib、sklearn 入门、疾病生理、pytest、WebSocket、Pygame | ⚠️ **必须靠"用"来学，不要靠"看书"来学**：数字滤波器与因果滤波 |
| **P1 提速** | ✅ 顺手学：MNE、MOABB、Kappa 与统计 | ⚠️ **给足整块时间**：谱估计（窗/STFT）、在线约束与稳定性 |
| **P2 加分** | ✅ 到点速成：Docker | ⚠️ **中期后专门排期**：黎曼几何 + EA；LSL 属 ⭐⭐ |

**读法**：
- 右上角（P0 + ⭐⭐⭐）是**唯一真正的技术门槛**——全队只有 1–2 人需要啃到能用；
- 右下角（P2 + ⭐⭐⭐）是**中期以后的事**，提前碰会挤掉 MVP 时间；
- 左上角（P0 + 容易）是**"人数问题"不是"难度问题"**——必须 4 人都过，靠的是每人独立跑一遍。

### 第 1 层 · 信号与数学（P0–P1 · ⭐⭐–⭐⭐⭐ · 约 75 h）

> **这一层决定项目"能不能做对"，而不是"能不能跑起来"。** 也是大一学生最容易跳过的部分。

| 技术 | 学到什么程度（**够用即停**） | 与本项目的关系 | 难度 |
|---|---|---|---|
| **线性代数** | 矩阵乘法、转置、**协方差矩阵**、特征值与特征向量、迹 | μ 波能量下降本质是**方差结构变化**；黎曼方法直接对协方差矩阵做分类 | ⭐⭐ |
| **概率统计** | 均值方差、正态分布、条件概率、**假设检验**、**Cohen's Kappa** | 验收指标就是 Kappa > 0.3；"扣除瞎猜蒙对后的真实水平" | ⭐⭐ |
| **信号与系统** | 采样定理、**时域↔频域**、傅里叶变换、**滤波器**（低通/带通/陷波）、相位延迟 | F1.3 因果滤波链 = 50 Hz 陷波 + 8–30 Hz 带通；**这些概念不理解，滤波器参数就是瞎调** | ⭐⭐⭐ |
| **数字滤波器实现** | IIR vs FIR、`scipy.signal.iirnotch/butter/sosfilt`、**`sosfilt` vs `filtfilt` 的区别** | ⭐**本项目最关键的一条工程知识**，见下方专项 | ⭐⭐⭐ |
| **窗函数与功率谱** | 汉宁窗、**STFT / Welch 法**、频率分辨率与时间分辨率的权衡 | F1.8 的"频带功率"就是谱估计；窗口 2 s @ 250 Hz = 500 点，决定分辨率上限 | ⭐⭐⭐ |
| **脑电生理** | 10-20 电极系统（C3/Cz/C4 在哪）、δ/θ/α/μ/β 频段、**ERD/ERS** | 阶段 0 验收明确要求：**解释 μ 节律 ERD/ERS 现象**；这是答辩必问 | ⭐ |
| **运动想象范式** | 左手/右手想象 → 对侧感觉运动区 μ 波下降；**脑机盲（15%–30%）** | 决定为什么要左右手、为什么有人怎么练都不行（范式问题，不是算法差） | ⭐ |

#### ⭐ 专项：为什么"因果滤波"必须第 2 周就搞懂（P0 · ⭐⭐⭐）

这是**本项目最容易埋雷、最难排查**的一条，也是把"会调库"和"懂信号"分开的那条线：

- `scipy.signal.filtfilt()` **前后各滤一遍**（零相位），离线分析常用、结果漂亮；
  但它**用了"未来"的数据** → **在线不可能实现**，因为在线时未来还没发生。
- 在线只能用**因果滤波**（`sosfilt` + 保留滤波器状态 `zi`），它会引入**相位延迟**，这是物理代价，不是 bug。
- 因此：**离线用 `filtfilt` 调得再准，搬到在线也可能失效。**

**必须掌握的三个具体动作**：
1. 知道 `filtfilt` 不能用于在线，能说出原因（用到未来数据）；
2. 会用 `sosfilt` + `zi` **分块喂入**（每次 100 ms / 25 点），且知道**块与块之间必须传递状态**——不传状态，块边界就会出现阶跃；
3. 能验证 **T3/T4 用例**：`分块喂入 == 一次喂入`（容差内）、块边界无跳变。

> 这直接对应验收 **A6 稳定化有效** 与 **伪在线一致性（与离线差 < 5%）**。
> 第 3 周那个"回放准确率与离线差 < 5%"的硬指标，**成败在第 2 周有没有把这件事弄明白**。

> 这三条是**团队最容易为了应付评审而越线**的地方，也是校企合作里最伤信任的地方。
> **宁可写"本期未做"，也不补造数据。**

| **Pygame** | 游戏循环、事件、碰撞、渲染、帧率 | F4 脑控弹球；**黄凯森先用键盘做出完整玩法，不等算法** | ⭐ |
| **JSON 契约实现** | 严格按冻结字段名/类型输出，`label_id` 与 `label` 必须同时成立 | 验收 **R-4**：输出消息必须满足 4.2 节全部字段约束 | ⭐ |
| **YAML 配置驱动** | 参数集中在单个 YAML，`cli show-config` 导出实际生效配置 | F7.1；也是"配置即证据"（章程 5.4） | ⭐ |
| **环形缓冲与滑窗** | 固定容量不增长、2.0 s 窗口 / 0.5 s 步长触发 | F1.6 + F1.7；**长跑 1 h 内存不涨**就是靠它 | ⭐⭐ |
| **长跑与压测** | 跑 1 h 看内存/耗时漂移；报 p50/p95/max | 验收 A4 + A10；**p95 < 50 ms 是红线** | ⭐⭐ |
| **LSL（Lab Streaming Layer）** | 概念、采样率/通道顺序对齐、`pylsl` 收流 | ④ 接企业设备；**通道顺序必须企业书面确认**（Q1） | ⭐⭐ |
| **Docker** | 写 Dockerfile、`docker build/run`、交付环境复现 | ⑥ 12/15：企业能自己部署 | ⭐ |

**✅ 结业考（12/15 前）**
1. 游戏端真的**订阅到消息并驱动画面**（不是"端口能连"）——验收 A7；
2. 能拿 `cli benchmark` 的数字，把端到端时间**拆成"窗口累积 vs 计算"两段**并解释瓶颈；
3. 企业的人能在**一台干净电脑上按文档 3 分钟内跑起来**——验收 A8/A9。

## 6. 明确不要学清单（**和学什么同样重要**）

> 大一的真正风险不是"学不会"，而是**把 10 周花在"看起来很厉害但本期用不上"的东西上**。
> 以下每一条都是《MVP 规格说明书》或《项目章程》明确划到范围外的：

| 🚫 不要学 | 为什么 | 什么时候再学 |
|---|---|---|
| **深度学习 / PyTorch / EEGNet / Braindecode / Transformer** | 数据量不够（单被试几百 trial）、跨被试常打不过传统方法、**对延迟毫无帮助**（计算只占端到端的 0.1%）；本期"明确不做" | **下学期或下一期**。要读，只读 EEGNet 一篇做答辩依据 |
| **从零造采集硬件 / 买放大器 / 焊电极** | 不造硬件；MVP 用 `mock` / `replay`，脑电帽借企业的 | 不需要 |
| **MATLAB / EEGLAB / ERPLAB** | 团队技术栈已定 Python；学第二套工具纯属重复投资 | 除非企业指定 |
| **fNIRS / EMG / 眼动多模态融合** | 属"多模态融合"高难度方向，**项目规划里不是本期内容** | 下一期 |
| **医疗诊断级 / 医疗器械法规（NMPA）** | 明确不做医疗诊断级产品；本期不碰患者数据 | 走产品化路线时 |

| **多脑区融合 + 区域注意力网络** | 企业点名的**探索性**方向，非 MVP 必需；能力建设上明确"不要一开始就上" | ④ 仅在有剩余时间时做**简单**消融 |

## 8. 三条给大一新生的实话

1. **这份项目里，"会用工具"比"懂原理"先到岗，但"懂原理"决定你能不能交付可信数字。**
   第 0 层（Python/NumPy/Git）一周就能上手；第 1 层（信号与滤波）才是真门槛，**不要跳过它去学深度学习**。

2. **本项目最值钱的能力不是算法，是"把自己做的事讲清楚、留得住证据"。**
   评审和答辩看的从来不只是代码，还包括：**配置、日志、实测数字、复盘结论**。
   每天一次 commit、每次实验落盘，成本极低，但决定成败。

3. **诚实是这份校企合作的最高技术含量。**
   合成数据只证明流程通，**绝不能当成绩**；MVP 阶段不报准确率。
   **宁可写"本期未做"，也不要补一个漂亮的数字。** 企业真正会记住的，是这份可信度。
