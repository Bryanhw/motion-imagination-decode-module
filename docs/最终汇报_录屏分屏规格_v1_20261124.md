# 最终汇报 · 录屏分屏规格（T2 v1 草案）

> 用途：确定**录屏为主**的展示形式（老师明确偏向），并固化**分屏布局**——
> 一半游戏、一半数据解码/控制台。这是 D2 正式录屏的硬规格，供黄凯森录制、王释贤搭启动脚本、蓝验收。
> 状态：**v1 草案**（DeepWorks 起草，2026-11-24），待黄/王/蓝对表。
> 底层依据：`docs/老师反馈落地任务清单_20261124.md` T2；衔接 T1 `docs/最终汇报_链路讲解稿_v1_20261124.md` §三收尾。
> 红线：全程**不报裸准确率**；所有驱动素材 = 公开数据集回放 / 工程自检，**非现场真人采集**；未训练/置信不足必然 idle。

## 一、分屏总布局（建议 16:9，1080p @30fps）

```
┌─────────────────────────┬─────────────────────────┐
│ 左半屏：游戏画面          │ 右半屏：Decoder / 控制台  │
│  MI Pixel Run platformer │  ├─① 实时脑电波形        │
│  （含 SOURCE 角标）       │  │    （当前 2s 窗滚动）   │
│                         │  ├─② 实时决策日志        │
│                         │  │    一行一个 JSON       │
│                         │  └─③ 关键状态灯           │
│                         │      攒窗/滤波/特征/分类/发送│
└─────────────────────────┴─────────────────────────┘
```

- 分辨率：**1920×1080 或 1280×720，@30fps**（沿用 A8 既有规范）。
- 左游戏 / 右控制台各占一半；**解码器终端文字必须 720p 下可读**（字号≥12pt 或终端放大 150%）。
- 录制方式：OBS 场景两个源并列（显示器/窗口采集，见 A8 执行手册 §1.6.2 同框思路），单机即可满足"左边游戏右边解码"；
  若走两机联动则按 A8 手册 B 方案投屏同框。

## 二、右半屏控制台三块内容：现状 vs 需补

> 原则：**能复用绝不新造**。规格只定义"要呈现什么"，实现责任见 §六。

### ① 实时脑电波形（当前窗口 2s，可滚动）
- **目标**：直观展示"进来的脑电长什么样"，配合口播"这是原始 EEG 的 2 秒窗"。
- **现状**：`bci-decoder` CLI 输出 console/jsonl/websocket，**没有现成 GUI 波形窗**。
- **实现路径（需补，轻量）**：一个只读监视脚本 `scripts/serve_waveform.py`（最小可行）：
  - 从同一 WS 输出 or 直接读 `output.record_path` 的原始窗口帧，用 matplotlib/pygame 画 8 通道 2s 滚动；
  或者**降级方案**：先以右半屏"终端 + 决策日志"为主，波形用 demo 配置文件里已有的回放画面代替，录屏周内再决定是否补波形 GUI。**不要为波形拖住录屏主路径**。

### ② 实时决策日志（一行一个 JSON）
- **目标**：展示冻结契约字段实时输出。
- **现状**：**已有**！`console` sink 一行输出一条决策；`jsonl` sink 落盘完整契约。
- **规格要求**：右半屏终端运行 `--outputs console`（或 console+jsonl），每行必须含：
  `label / label_id / confidence / probs / state / compute_ms / window_seconds / t_data / t_wall`（冻结 9 字段）。

### ③ 关键状态灯（窗口已攒 / 滤波中 / 特征计算 / 分类 / 已发送）
- **目标**：让观众看到"每一步在跑"，呼应 T1 链路图（滤波→切窗→特征→分类→发送）。
- **现状**：无专门状态灯 UI。
- **实现路径（需补，最简）**：监视脚本里按决策进程打 5 个状态点日志（攒窗→滤波→CSP→LDA→已发送），
  显示为终端行或几个字符灯。**同样为录屏加分项，不做不死板**；最低下限 = ②决策日志已足够证明链路。

> **T2 本段硬规格 = “游戏 + 决策日志”两样必须有；波形 / 状态灯为加分项，尽力做、不扣分。**

## 三、素材三段（每段开头 1 秒黑场标识数据源）

### 段 1｜公开 EEG 回放驱动游戏（个人校准模型）
- 画面：左 = MI Pixel Run 被个人校准模型驱动；右 = 解码器输出连续决策。
- 素材：BCI IV 2a **22 通道回放**（`m4_prepare_replay.py` 导出 → `calibrate.py` 重训个人模型），
  或已有的 `demo_game_ws.yaml` / `demo_game_eegmmidb.yaml` 链路先出画面。
- 说明：这里展示"校准后个人模型 + 真实 EEG 回放 + 游戏被驱动"完整闭环。
- 黑场字幕：**“公开数据集回放 · BCI IV 2a”**。

### 段 2｜安全演练（停解码端 → 看 idle 安全态）
- 画面：演示到一半**故意停掉解码器/断 WS** → 游戏角色停在安全态（`NONE`/`idle`），再重启恢复。
- 素材：`demo_game_ws.yaml`（WS 断线重连自带 0.5s 重连 + 安全退 NONE，回归测试齐备）。
- 说明：这是红线的可视化——"没把握就什么都不发"。
- 黑场字幕：**“安全演练：断流 → idle 安全态”**。

### 段 3（可选）｜键盘 / 合成作工程通路对照
- 画面：键盘可玩（`--mode keyboard`）或合成 mock 工程通路，作为"链路先行验证"对照。
- 黑场字幕：**“工程通路对照 · 键盘 / 合成信号”**。

> 三段开头各置 **1 秒黑场 + 数据源字幕**（沿用既有规范：录屏素材段首明确数据源，避免误会为真人脑控）。

## 四、可复用的实际命令 / 配置（已核实存在）

| 用途 | 配置 / 命令 | 说明 |
|---|---|---|
| 游戏 WS 联调 | `configs/demo_game_ws.yaml` | source=mock 仅**工程自检**；演示给"游戏被驱动画面" |
| 回放类别切换 | `configs/demo_replay_switch.yaml` | 回放左/右规律切换，A3 链路持续验证级 |
| 真实 EEG 回放 | `m4_prepare_replay.py` → `calibrate.py`（22ch）→ `replay` | 公开数据个人模型回放（D1→D2 交接物） |
| 断线安全演练 | `demo_game_ws.yaml` + 录到一半 Ctrl+C 解码端 | 角色回 NONE / 重连恢复 |
| 键盘对照 | `game\platformer\main.py --mode keyboard`（或 pong/jsonl 兜底） | 段 3 可选 |
| 模型准备 | `python scripts/bootstrap_demo.py` | 生成 demo_csp/demo_lda/ood |

- 操作顺序（王释贤按此搭**固定启动脚本** `scripts/start_recording.ps1`）：
  1. `bootstrap_demo.py` 备好 demo 模型；
  2. 启动游戏（`--mode ws`，`ws://127.0.0.1:8765`）；
  3. 启动解码端（`--outputs websocket,console,jsonl`，record_path 固定）；
  4. OBS 开录（左游戏窗口 + 右解码终端 两源同框）；
  5. 每段前黑场 1s + 数据源字幕。
