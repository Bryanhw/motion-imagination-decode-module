## 4. 数据链路（BCI IV 2a = `BNCI2014_001`）

- **数据集**：BCI Competition IV 2a——9 受试 × 2 session（`0train`/`1test`），每 session 6 run × 48 trial = 288 trial；**4 类运动想象** `left_hand`(1)/`right_hand`(2)/`feet`(3)/`tongue`(4)；22 EEG 通道 + 1 EOG；250 Hz。
- **moabb 读取口径**：`MotorImagery`(events=[left/right/feet/tongue], n_classes=4) → X 形状 `(576, 22, 1001)`（2 session × 288）、y `(576,)`、meta 含 `subject/session/label`。

### 4.1 关键坑：moabb 官方源给坏文件（已实锤）

观测：`paradigm.get_data(subjects=[1])` 报 `OSError: could not read bytes`（scipy zlib 展开失败）。排查过程：

1. 先怀疑本地下载残缺——但 NEMAR 镜像文件 SHA-256 与 manifest 完全匹配，且**手动 `loadmat` 深层展开完全成功**。
2. monkey-patch `moabb.datasets.bnci.base.loadmat` 打印**实际读取路径**：moabb 读的是 `D:\...\mne_data\MNE-bnci-data\~bci\database\001-2014\A01T.mat`（仅 14 MB），**不是** NEMAR sourcedata！
3. 结论：moabb 1.7.2 对 `BNCI2014_001` 走**官方镜像源**下载到 `MNE-bnci-data\...`，官方源返回的 `.mat` 是**残缺坏文件**（14 MB），scipy 展开时崩溃。

### 4.2 解法：NEMAR 镜像 → 复制到 moabb 期望路径（已实证有效）

- 数据真实来源 URL 模式（NEMAR S3，public-read、支持 Range 请求）：

  `https://nemar.s3.us-east-2.amazonaws.com/nm000139/objects/SHA256E-s<size>--<sha256>.mat`

  其中 `<size>` = 文件字节数、`<sha256>` = 文件内容 SHA-256（NEMAR 的 annex key 即哈希，**可作完整性基准**）。地址本在 `mne_data\NEMAR\nm000139\sourcedata\sourcedata_provenance.json`（manifest，含全部 9 受试 2 session 共 18 个文件、合计约 744 MB）。

- subject 1 已下载并校验（SHA-256 双匹配，与 manifest 完全一致）：

| 文件 | 字节数 | SHA-256 |
|---|---|---|
| A01T.mat | 42,806,453 | `054f02e70cf9c4ada1517e9b9864f45407939c1062c6793516585c6f511d0325` |
| A01E.mat | 43,772,146 | `53d415f39c3d7b0c88b894d7b08d99bcdfe855ede63831d3691af1a45607fb62` |

- 复制到 moabb 期望路径后，moabb **判定文件已存在、跳过下载、直接读完好数据**：

  `MNE-bnci-data\~bci\database\001-2014\A01T.mat` / `A01E.mat`

### 4.3 下载方法与避坑（实测）

- **用 `curl -sSL --fail -o <目标>` 一次性下载**；**切勿 `curl -C -` 断点续传**——实测续传会把文件写坏（SHA-256 对不上、scipy 崩）。
- 下载后**必须 SHA-256 校验**（`Get-FileHash`），再复制覆盖到 moabb 路径。
- NEMAR S3 对**16 并发**会 `ConnectionResetError 10054`——moabb/nemar-py 自带并行下载不可靠；一次只下 1 个文件最稳。
- S3 速度约 350 KB/s（subject 1 两个文件约 4 分钟）。9 受试 18 文件约 744 MB，后台分批下载约 35–40 分钟。
- bash 工具有 120 s 超时会**杀整个进程树**：长下载要「后台启动即返回 + 短轮询」，或接受「被杀后重跑」。

## 5. 评测骨架脚本

`bci-decoder/scripts/m3/offline_eval_bci4_2a.py`（入库）。

运行方式（Windows PowerShell 5.1，**不要用 `&&`**，在仓库根）：

```powershell
$env:PYTHONPATH = "D:/校企合作项目/bci-decoder"
# 自检（不下载、合成信号、验证代码路径）
.deepworks/venv_m3/Scripts/python.exe bci-decoder/scripts/m3/offline_eval_bci4_2a.py --quick
# 只读入（subject 1，确认数据链路）
.deepworks/venv_m3/Scripts/python.exe bci-decoder/scripts/m3/offline_eval_bci4_2a.py --subjects 1 --load-only
# 完整回测（CSP+LDA 5-fold + OOD 域内检测）
.deepworks/venv_m3/Scripts/python.exe bci-decoder/scripts/m3/offline_eval_bci4_2a.py --subjects 1 --with-ood
# 全数据集正式评测（9 受试，11/10 用）
.deepworks/venv_m3/Scripts/python.exe bci-decoder/scripts/m3/offline_eval_bci4_2a.py --subjects 1 2 3 4 5 6 7 8 9 --with-ood
```

参数：`--subjects`（默认 1）、`--pipeline csp|riemann`（默认 csp）、`--quick`（合成自检）、`--load-only`（只读入退出）、`--with-ood`（追加 OODDetector 域内检测）、`--mne-data <dir>`（默认 D 盘 `.deepworks/mne_data`）。

实现要点：
- 读入用 moabb `MotorImagery`，分段与单位与 MVP 口径对齐；分类用 `LDA(solver="lsqr", shrinkage="auto")`（svd 不支持 shrinkage）。
- OOD 段在全量训练上 fit 一次 `OODDetector`（`bci_decoder/bci_decoder/pipeline/ood.py`，接口 `__init__(method, chi2_quantile, score_scale, strength_floor_enabled)`，`is_outside` 标量接口需循环），`--with-ood` 报**域内检出率**（期望≈0，=域内不误杀自检标尺）。正式版需改为按折拟合 + 增加 idle 兜底评测，待 M2 后口径拍板。
- 脚本 docstring 含纪律提示（MVP 阶段不得对外报准确率）。

## 附：本次预研踩过的环境/工具坑（备忘）

- PowerShell 5.1 here-string `@"..."@` 会吃掉反斜杠 → 内嵌 Python `-c` 代码里路径用正斜杠（`D:/...`）或写脚本文件。
- PowerShell 单/双引号里的 `\n` 不是换行；here-string 首尾换行与文件行尾对不齐会导致字符串匹配按 0 次——改文件优先用 `edit` 工具或 `[System.IO.File]::ReadAllText/WriteAllText` + `Replace`（保证 UTF-8 不丢中文）。
- `$host` 是 PowerShell 保留只读变量，别当参数名（用 `$base` 等）。
- 中文输出乱码：脚本打印前 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`；PowerShell 侧先 `[Console]::OutputEncoding=$OutputEncoding=[System.Text.UTF8Encoding]::new($false)`。
- 脚本/日志里**避免 `✓`**（GBK 控制台编码崩）。
- `edit` 工具对该骨架脚本出现过 `DEEPWORKS_FILE_WRITE_LOCK_TIMEOUT`，遇锁改用 PowerShell 文件操作。
