      │    state / compute_ms / window_seconds）

- **提升点**：老师点名“数据太少”。现状：M4 训练/评测仅靠 BCI IV 2a(22 通道) 与 PhysioNet(8 通道) 两类公开数据，受试/样本规模有限。**本阶段不引入、不更换设备**（设备即 XMuse，已实锤主 4 通道 TP9/AF7/AF8/TP10 不在运动区——此点只作记录，**不再追换设备/外接电极路线**）。回应的做法是：**在不改模块契约（固定 8 通道 `C3,Cz,C4,CP3,CP4,P3,P4,Oz`@250Hz）的前提下，扩充可用公开数据的量与来源**，让训练/评测基线更扎实。

### T4 行业标准对比表（响应反馈 5）

- **提升点**：演示需要“我们的重要数值 vs 行业参考”的对比，且**优势、不足都要讲**。
- **建议方案（对比口径草案，含红线）**：

  | 指标 | 我们的数字（可对外口径） | 行业/标准参考 | 结论 |
  |---|---|---|---|
  | 解码质量 | 窗口级 Kappa ≈0.36（个人校准后，9 人均值） | BCI 竞赛惯例达标线 0.3 | 达标，**不足**：窗口级为保守口径 |
  | 解码质量(trial 级) | 0.466/0.481（M3 同数据） | 同上 0.3 | 超线 |
  | 免校准跨被试 | ≈0.19（近随机） | 领域公认“无校准跨被试难” | **如实披露不足**，引出个人校准 |
  | 算力延迟 | compute p95≈3.7ms（30min 长跑实测） | 本项目预算 <50ms | 余量充足 |
  | 长跑稳定性 | 34.9min / 0 error / 内存无增长 | 项目门槛 30min 连续 | 达标 |
  | 端到端响应目标 | ≤3s（攒窗 2s 为主因） | 交互类应用常见容忍区间 | **不足**：瓶颈是生理窗口，非算法 |

  1. 数字只来自：M3 评测（BCI IV 2a 公开数据）、M4 D1（个人校准对比）、B1（工程稳定性）——均为公开数据集回放/工程自检；
  2. **不报裸准确率**；Kappa/ITR/工程指标可报；
  3. “不足”至少带 3 条：免校准≈随机、窗口级 Kappa 偏低、端到端 3s 瓶颈在生理窗口（和个体差异/BCI illiteracy 一并讲，正接叙事“试玩门”）。
- **分工**：DW 结合 M3/M4 数字起草 → 阎 数字复核 → 蓝 口径审（对不对外发布拍板）。
- **死线**：12/06 前初稿并入演示稿。
