## Who It's For

### Primary User: 李工（企业侧集成工程师）

用大白话说：**李工是翔宇医疗做康复/游戏软件的工程师。他要的不是"脑电论文"，而是一个能塞进他自己程序里的"意图输出盒子"。**

**Their Current Pain:**
- 拿到的都是**研究代码**（跑出一个准确率曲线图就结束了），**没有一个能直接接进产品的接口**。
- 延迟**不透明**：不知道从"人开始想象"到"画面动"中间到底花了多久，无法向产品经理交代。
- 信噪比低时会**乱输出**——一个随机指令足以毁掉一次康复训练体验。
- 换设备（通道数、通道顺序、采样率一变）就要**重写一遍**。

**What They Need:**
- **一条命令就能启动**，三分钟内看到结果，不用先读一天源码。
- **一份写死的 JSON 消息契约**（字段固定、不增删），接进自己的程序不用猜。
- **实测的延迟数字**，以及"这个延迟花在哪、能不能接受"的解释。
- **安全兜底**：没训练 / 不可信时**老老实实输出 `idle`（不动）**，绝不给游戏发随机左右指令。

### Secondary User: 小王（本项目团队成员 / 现场演示者）

大一学生，边学边做。需要：能照着文档在**任何一台同学的笔记本**上复现；演示时**一次成功**；答辩时能讲清"延迟花在哪"。

### Example User Story

"李工是翔宇医疗康复产品线的软件工程师。他每天要面对的是：算法同学给了他一份能跑出漂亮曲线的研究代码，但**没有接口、没有契约、没有延迟数字**。他需要把这份能力嵌进康复小游戏里，却不知道接哪个函数、输出长什么样、慢了算谁的。他希望有一个模块——`启动 → 订阅 → 收到 JSON → 挡板动`——四步之内就能联调成功，而且**在他没训练模型的时候，它只是安静地什么都不做**。"

## The Problem We're Solving

运动想象（Motor Imagery, MI）解码在工程上有三个**隐形陷阱**，它们不会在论文里出现，但会让产品做不出来：

1. **在线必须因果滤波**。离线常用的零相位滤波（`filtfilt`）会用到"未来"的样本，在线套用会让块边界跳变、特征剧烈抖动——**离线能跑，在线失效**。这一点有官方文档依据（SciPy / MNE-LSL 均描述在线滤波为 "IIR causal filter"）。
2. **延迟由"等窗口"决定，不由算法决定**。滑窗 2.0 s 意味着端到端延迟里约 99.8% 的时间在**攒数据**，单次计算的毫秒级耗时几乎可以忽略。所以"换个更强的模型"救不了跟手性。
3. **低信噪比下容易抖动/误触发**。单帧决策直接驱动画面 → 画面抽搐、体验崩溃。

**Why now:** 校企合作已经对接，企业侧要的是**可嵌入的软件模块**，而不是又一份研究报告；团队只有 10 周，必须先打通链路、再谈精度。

**Why Existing Solutions Fall Short:**
- **`mne-lsl` / `EEG-ExPy` / `Timeflux` / `BrainFlow`**: 提供的是"取流—同步—分段—分类"的**积木**，官方定位里**没有**"把解码结果定义成面向游戏的消息契约"这一层。
- **`mne-lsl` 的官方实时解码示例**: 产物是一张 `Classification score` 曲线图（`ax.plot(...)`），**不是结构化消息**——没有 `idle`、没有置信度门限、没有字段冻结语义。
- **`pyRiemann` / `moabb`**: 一个是分类算法库，一个是**离线**基准评测——都不解决实时缓冲、因果滤波与消息封装。
- **`mne-realtime`**: 官方 README 已写明被 MNE-LSL 取代（"This project is discontinued in favor of MNE-LSL"），**不建议采用**。

结论：这一层的缺失是**应用层契约 + 工程封装**的问题。它取决于具体游戏节奏（2.0 s 窗口 / 0.5 s 步长）与风控策略，通用框架为了可复用，通常把它留给使用方——**所以必须自己写**。

> 诚实标注：以上"框架没提供这一层"是**已核实的官方事实 + 一条推断**（详见 `research-BCI-Decoder.md` §3.7）。没有任何文档直接写"我们不提供游戏黑盒模块"。

## User Journey

### Discovery → First Use → Success

1. **Discovery Phase**
   - How they find us: 校企合作对接会、课程评审、Demo Day 现场。
   - What catches their attention: **"想一下，球就动了"**——一句话能演示的画面，而不是一张准确率表。
   - Decision trigger: 现场看到**从启动到出结果 ≤ 3 分钟**，且延迟有实测数字。

2. **Onboarding (First 5 Minutes)**
   - Land on: 终端 + 一份 README（不是网站，本项目没有 Web 界面）。
   - First action: 在 `bci-decoder/` 里跑一条启动命令，选 `mock` 数据源。
   - Quick win: 屏幕上**立刻滚出 JSON 消息**（`label` / `confidence` / `probs`），证明"链路是活的"。

3. **Core Usage Loop**
   - Trigger: 想看自己的意图能不能被识别。
   - Action: 切换 `replay` 或接上游戏 → 想象左手 / 右手移动。
   - Reward: 游戏挡板**跟着动**；不想动的时候它**真的不动**（`idle`）。
   - Investment: 模块装在自己机器上、契约写进自己的代码里——**用起来了就换不掉**。

4. **Success Moment**
   - "Aha!" moment: 第一次"只是想象了一下，挡板就动了"。
   - Share trigger: 演示现场观众自己上手试一次。

## MVP Features

### Must Have for Launch

#### 1. F1 · 在线解码链路（`mock` / `replay` 两种数据源可切换）

- **What:** 一条从 EEG 数据到决策输出的完整在线管道：因果滤波 → CSP 特征（4 维）→ LDA → 决策稳定化。数据源可切换：`mock`（合成，工程自检用）/ `replay`（回放离线记录，模拟真实节奏）。
- **User Story:** 作为**企业集成工程师**，我希望**不改代码就能切换数据源**，这样我**没有真实设备时也能先把链路联调通**。
- **Success Criteria:**
  - [ ] 两种数据源都能持续稳定输出消息，不崩、不静默。
  - [ ] 在线链路使用**因果滤波**（`sosfilt` + 跨 chunk 保持 `zi` 状态），**不使用** `filtfilt` / `sosfiltfilt`。
  - [ ] 通道顺序锁定为 `C3, Cz, C4, CP3, CP4, P3, P4, Oz`，不被"顺手重排"。
  - [ ] `replay` 模式下能跟上类别切换（跟得上数据的时间轴）。
- **Priority:** P0 (Critical)

#### 2. F2 · 输出接口（`console` + `jsonl`）

- **What:** 每条决策输出一行 JSON，同时打印到终端并落盘为 `.jsonl`。字段与冻结契约**逐字段一致**。
- **User Story:** 作为**企业集成工程师**，我希望**拿到一份固定的字段表**，这样我**接自己的程序时不用猜、也不会因为上游改字段而崩**。
- **Success Criteria:**
  - [ ] 字段集合严格为 `t_data / t_wall / label / label_id / confidence / probs / state / compute_ms / window_seconds`，**不增不减**。
  - [ ] `label_id == -1` **当且仅当** `label == "idle"`。
  - [ ] `probs` 恒定长度 2、和为 1；所有数值为 JSON number，不用字符串包装数字。
  - [ ] 输出可落盘为合法 JSONL（逐行可解析）。
- **Priority:** P0 (Critical)

#### 3. F3 · 决策稳定化（EMA 平滑 + 连续 3 次一致性投票 + 置信度门限）

- **What:** 在原始 LDA 输出之上做三重稳定化：指数滑动平均平滑概率、连续 3 次一致才切换标签、置信度不足时输出 `idle`。
- **User Story:** 作为**现场演示者**，我希望**画面不要抽搐**，这样**观众看到的是"能用"，而不是"算法在抖"**。
- **Success Criteria:**
  - [ ] 连续 3 次一致才切换标签（不满足则维持上一状态）。
  - [ ] 置信度低于门限 → 输出 `idle`。
  - [ ] **未训练 / 模型缺失 → 恒输出 `idle`**，绝不发送随机左右指令。
  - [ ] 伪迹只**标记不丢弃**；超阈值时降级为 `idle`。
- **Priority:** P0 (Critical)

#### 4. F4 · 脑控弹球游戏 Demo

- **What:** 一个可玩性完整的弹球/接球小游戏，**先做键盘版本**（左/右/停），再把输入替换为解码消息。
- **User Story:** 作为**团队演示者**，我希望**游戏和算法能并行开工**，这样**算法没就绪时我也不会空等**。
- **Success Criteria:**
  - [ ] 键盘版本完整可玩：有得分、有反馈、可重来。
  - [ ] 切换到解码输入后，"想象 → 挡板动"现场可演示。
  - [ ] `idle` 时挡板**保持不动**（不是随机方向）。
- **Priority:** P0 (Critical)

#### 5. F5 · WebSocket 输出打通

- **What:** 模块把消息流通过 WebSocket 推给游戏端，游戏**实际订阅并驱动画面**。
- **User Story:** 作为**企业集成工程师**，我希望**用现成的消息通道订阅结果**，这样我**不需要自己去读文件、也不需要理解脑电细节**。
- **Success Criteria:**
  - [ ] 游戏端**真的收到消息**并驱动了画面（有联调录屏为证）。
  - [ ] 连接断开时可恢复，不静默丢消息。
  - [ ] 若 `websockets` 装不上/跑不通，降级方案生效（`jsonl` 文件轮询 或 本地 TCP）。
- **Priority:** P0 (Critical)

### Nice to Have (If Time Allows)

- **演示页（延迟分解可视化）**: 把 `T_accumulate`（窗口，约 2000 ms）与 `T_compute`（毫秒级）画成对比图，答辩第 3 页直接用。
- **长跑自检脚本**: 连续 1 h 跑链路并记录内存曲线，产出验收项 A10 的证据。
- **证据归档脚本**: 一键把测试输出、benchmark 结果、录屏清单收进 `docs/evidence/`。
- **控制消息最小实现**: 冻结契约定义了 `start` / `stop` / `calibrate` / `load_subject` 四条（§4.4），但 MVP **只需响应 `start` / `stop`**（F5.2，P2）；其余两条按约定**忽略并记日志**，不得崩溃或断开连接。

## Look & Feel

**Design Vibe:** 干净 · 跟手 · 可复现 · 诚实
> ✅ **已确认保留**（2026-10-15，团队确认不替换）。这 4 个词是本品的设计基调；下方 4 条视觉原则是它们的具体落法，冲突时以原则为准。

**Visual Principles:**
1. **跟手优先**：任何让画面抽搐的实现都不算"完成"——宁可输出 `idle`，也不要乱动。
2. **诚实不装**：不显示没有依据的数字；不把 `mock`/`synth` 的结果当作成绩展示。
3. **一眼看懂**：演示界面字号大、对比强，投影仪上后排也看得清；终端输出字段对齐、可读。
4. **失败也是安全态**：模型缺失时界面应当"安静地不动"，而不是报错刷屏。

**Key Screens/Pages:**
1. **脑控弹球窗口**: 唯一的"用户界面"。显示得分、运行状态、当前挡板位置；标题栏或角落显示最近一条消息。
2. **模块运行视图（终端）**: 滚动输出 JSON 消息与状态机变化；`idle` 与 `running` 用不同颜色/前缀区分。
3. **演示页（答辩用，Nice to have）**: 第 1 页"这是什么"，第 2 页"现场演示"，第 3 页"延迟花在哪"。

## Technical Considerations

**Platform:** Windows 笔记本为主（PowerShell 5.1，**无独立显卡**）；交付物是 **Python 模块 + 可选 WebSocket 服务**，不是网站、不是移动应用。
**Responsive:** 不适用（无 Web UI）；游戏窗口需适配演示机分辨率与投影。
**Performance:**
- 单次计算耗时 **p95 < 50 ms**（验收红线 R-3）
- 端到端响应 **≤ 3 s**（2.0 s 窗口 + 计算）
- 启动到出结果 **≤ 3 分钟**
- 连续运行 **1 h** 不崩、内存不增长
**Accessibility:** WCAG 2.1 AA **不适用**（非面向公众的 UI 产品）；替代要求 = 投影可见（大字号、高对比）+ 终端输出可被屏幕阅读器线性读取。
**Security/Privacy:**
- **不新增现场真人采集**（伦理未走完）；`replay` 回放公开数据集（真实受试者采集，本项目仅回放、不新采）；`mock` 为实时合成数据（非受试者数据，仅工程自检）。
- 企业设备资料（型号、固件、引脚/通道定义）属翔宇医疗资料，**不得贴进任何 AI 对话或外部服务**。
- 不引入付费云服务、不做数据外传。
**Scalability:** MVP 单机单用户即可，不做并发扩展；架构上保留"换数据源/换模型"的可替换点。

**关键约束（冻结，不得擅改）**

| 项 | 值 |
|---|---|
| 类别数 | **2 类（左手/右手）+ `idle`** |
| 滑窗 / 步长 | **2.0 s / 0.5 s** |
| 采样率 / 通道数 | 250 Hz / 8 通道 |
| 通道顺序 | `C3, Cz, C4, CP3, CP4, P3, P4, Oz`（**顺序即语义**） |
| 特征 / 分类器 | **CSP + log-方差（4 维）+ LDA**（2026-10-20 由频带功率 16 维切换，经 `MVP规格说明书` 第 9 节登记 v1.1.3） |
| 滤波方式 | **在线必须因果**（`sosfilt` + 跨块 `zi`） |

**输入数据流**：形状 `(n_channels, n_samples)`、单位 µV、250 Hz、8 通道、建议 100 ms 一块。

**输出消息（每行一条 JSON）**

```text
{
  "t_data": 12.345, "t_wall": 8412.551,
  "label": "left", "label_id": 0, "confidence": 0.83,
  "probs": [0.83, 0.17], "state": "running",
  "compute_ms": 1.2, "window_seconds": 2.0
}
```

> 完整字段表、控制消息与状态机见 [`MVP规格说明书.md`](MVP规格说明书.md) 第 4 节（自 2026-10-13 冻结，变更须走其第 9 节流程）。

## AI / Automation Scope

**Product AI:** **None** —— 交付物是**确定性信号处理链路**（滤波 → CSP 特征 → LDA → 后处理）。MVP **不含任何深度学习或大模型组件**，不需要 GPU。

**User Outcome:** 不适用（产品运行不调用大模型与深度学习）。比"智能效果"更重要的是**可复现**：同样的输入给同样的输出。

**Data Access:** 无大模型或深度学习组件读写任何产品数据。

**Provider / Retention:** 不适用——**不接任何 LLM provider**，无训练/留存设置需要核实。

**Output Contract:** 产品输出是**确定性 JSON 消息契约**（上表字段冻结），不是 AI 输出。

**Human Confirmation:** 不适用（无大模型或深度学习组件动作）；对应的安全机制是**未训练/不可信 → 恒输出 `idle`**。

**Evaluation:** 不适用（产品运行不调用大模型与深度学习）。替代物 = 单元测试 + 端到端测试 + 伪在线回放验证。

**Telemetry / Cost:** 无遥测、无外呼；**成本 ￥0**（全部依赖开源）。

**开发过程的 AI（与产品无关，但工作流要求声明）：** 团队使用 AI 编码助手（DeepWorks / `AGENTS.md` + `agent_docs/` 体系）辅助开发、写测试、写文档、解释报错。
**边界三条**：① 企业设备资料不贴；② 真实受试者数据不贴；③ AI 生成的关键代码必须人工复核——尤其是**因果滤波、通道顺序、契约字段**三处（错了会稳定产生错误结果，且极难排查）。
