## 2. 任务 B1 —— 稳定性验收（最重要）

### 2.1 这是什么 / 为什么做

- **背景**：最终汇报时要当场演示解码程序一直跑，跑到一半崩了/卡了就翻车。
- **目标**：喂一段公开数据让它"像放录像带一样"反复放，连续 30 分钟，证明：
  1. **不崩溃**（进程不退出、没有报错堆栈）；
  2. **内存不越长越多**（占用不随运行时间一直涨）；
  3. **延迟在预算内**：单次计算 p95 **< 50 ms**（规格书硬红线）。
- **说明**：早有"1 小时 mock 长跑"证据（A10），但那是造出来的假数据。B1 要的是
  **回放真实数据文件、按真实节奏循环**——更贴近演示现场，所以用 `replay` 源跑。

### 2.2 用什么命令（照抄即可，都在 `bci-decoder/` 目录下）

```powershell
.venv\Scripts\python.exe -m bci_decoder.cli run --config configs/demo_replay_switch.yaml
```

- 该配置是 `replay` 源 + `loop: true`（60 秒数据反复放）+ `realtime` 真实节奏。
- 想**实测 30 分钟**就**不要**加 `--chunks`（加 `--chunks` 会强制 realtime=false 变快跑失真）。
- 跑的过程另开终端看内存：`Get-Process python | Select Id,@{n='RSS_MB';e={[math]::Round($_.WorkingSet64/1MB,1)}}`

### 2.3 什么叫"做完"（验收标准）

1. 连续运行 **≥30 分钟**，进程没退出、日志**没有 error / traceback**；
2. 决策次数与时长对得上（约 30min ÷ 0.5s ≈ 3600 次量级）；
3. 内存不持续增长（多次采样 RSS 稳定）；
4. 计算耗时 p95 **< 50 ms**（cli 结束时打印 `计算耗时统计`）；
5. 日志存 `artifacts/soak/`（不入库），写简短证据 `docs/evidence/M4_*/B1_稳定性replay30min_*.md`。

> 我会实际启动一次 30 分钟跑，把日志和耗时统计抓下来当证据。

## 3. 任务 B3 —— LSL 接口层 mock 验证

### 3.1 这是什么 / 为什么做

- LSL 是"脑电数据上网"的标准接口。真设备来了数据就走 LSL 进来。
- 现在没真设备，要**自己发一条假流**，把"怎么发现流、怎么抓数据、怎么判断"整段代码路径跑通。
- 提前确认将来真设备一到，接流部分**代码没毛病**（只差换真数据）。

> 红线：仿真数据**只用来验证链路通不通**，**绝不对外报性能/准确率**。

### 3.2 命令（两个终端，都在 `bci-decoder/` 下）

```powershell
# 终端 1：发布 8 通道仿真 EEG 流（真实节奏）
.venv\Scripts\python.exe scripts/lsl_sim_stream.py --seconds 30
# 终端 2：发现流 → 抓取并判读
.venv\Scripts\python.exe scripts/lsl_selftest.py --list
.venv\Scripts\python.exe scripts/lsl_selftest.py --check 20
```

### 3.3 什么叫"做完"

1. `--list` 能发现仿真流 `sim_mi_8ch`；
2. `--check` 能抓样本并给出通道/采样率判断；
3. 记证据 `docs/evidence/M4_*/B3_LSL_mock_*.md`（"无设备、仿真流、链路通"）；
4. 判定 LSL 是否满足"真机接入的前置代码就绪"。

> 已有一版闭环（`lsl_sim_stream.py`+`lsl_selftest.py`，pytest 66/66），B3 是重跑并固定为本轮证据。

## 4. 任务 B2 —— Docker 草稿评估（优先级最低）

### 4.1 这是什么 / 为什么做

- Docker 把程序和依赖打包成"集装箱"，别人不用装一堆东西就能一键运行。
- 目标是写**草稿评估**这条路能不能走、值不值得正式做。
- **只出草稿，不正式交付**（组长已拍板）；手头无 Docker，只做**书面评估**，不要求实跑。

### 4.2 要产出什么

1. **可行性结论**：能打包（对象是 `bci-decoder` 解码模块，纯 CPU、可离线、适合容器）；
2. **Dockerfile 草稿**（骨架版）；
3. **实跑前必做验证清单**（WS 端口、pylsl 在 slim 镜像加载等）；
4. 结论：**正式做排到交付期，不阻塞功能件**。

### 4.3 什么叫"做完"

- 产出 `docs/evidence/M4_*/B2_Docker草稿评估_*.md`：可行性表 + Dockerfile 草稿 + 验证清单。
- 不需要真跑 Docker。
