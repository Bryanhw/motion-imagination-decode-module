## Product Overview

**App Name:** BCI-Decoder-Game（脑控弹球 / BCI-Pong）

**Tagline:** 想象左手或右手 —— 让挡板替你接住球

**Launch Goal:** 在 10/27 的现场演示上，用**一块看得懂的窗口**证明「运动想象 → 解码 → 动作」这条链路成立：先交付**键盘版完整玩法**（不依赖解码器、随时可兜底），再交付**解码消息驱动版**（游戏实际订阅消息并驱动画面，不是"端口能连"）。

**Target Launch:** 里程碑 ② **2026-10-27**（MVP 硬节点，不可延；`MVP规格说明书` §10.1、§11.2）。

**一句话类比**：解码器是"发动机"，本产品是"仪表盘 + 方向盘"——它让发动机的转速变成观众**一眼能看懂**的动作。

## Who It's For

### Primary User: 团队演示者（现场讲解 + 答辩者）

**他们的处境**：算法侧跑得动，但结果只是终端里一行行 JSON。面对评审/企业/同学时，需要**在 3 秒内**证明"脑子里想的东西真的改变了屏幕"。演示环境常常是陌生的投影仪 + 会议室光线。

**他们需要**：
- 一条命令就能起来，**不依赖解码器也能先玩起来**（演示前兜底）；
- 大字号、高对比、后排也看得清；
- **失败要安静**：模型缺失时画面安静地不动，而不是弹错误框或刷红字；
- 不需要向观众解释技术细节，画面自己会说话。

### Secondary User: 内测试玩者（团队外同学）

**他们的处境**：被拉来做小白鼠，第一次接触脑控游戏。

**他们需要**：不用读文档就能上手（键盘版即可），玩完能给出"跟不跟手""动不动"的直觉反馈。

> **不是本产品的用户（但很重要）**：合作企业（翔宇医疗）的康复/游戏应用是**解码模块**的最终受益方；本期弹球只是**Demo 载体**，不是交付给企业的产品形态。企业未来客户端是否用 Unity 属**另一条分支**（见 Open Questions）。

### Example User Story

> 作为一名**团队演示者**，我想在投影仪上启动一个弹球游戏，先按左右键确认它手感正常，再把输入切到解码消息流；当我**只是安静坐着不做想象**时挡板必须**一动不动**，而当我**想象左手**时挡板**立刻左移**并让我得分——**这样我就能在现场一眼证明链路成立，而不是念一串日志。**

## The Problem We're Solving

**核心问题：「解码成没成」肉眼不可见。**

链路跑通 ≠ 能被看懂。`console` 与 `jsonl` 是**给工程师看的**：一屏 JSON 无法向非技术观众证明因果，也无法在答辩现场制造"哇"的一声。更危险的是——**讲不清 = 看起来没做**。

**具体痛点（按疼痛程度排序）**：

1. **因果不可见**：观众看不到"想象 → 动作"的对应关系，只能听你转述。
2. **失败不可读**：模型缺失或置信度不足时，若界面弹出报错/乱动，会被误认为"程序坏了"；而真相是**系统按设计安全降级为 `idle`**。
3. **演示不可兜底**：现场没有"键盘版"备用形态时，一次解码侧故障就会让整场演示归零。
4. **控制率是 2 条/秒**（窗口 2.0 s / 步长 0.5 s，冻结）：任何按"快节奏连击"设计的玩法都会**必然抽搐**，必须为 2 Hz 设计手感。

### Why Existing Solutions Fall Short

| 替代方案 | 为什么不够 |
|---|---|
| 直接看终端日志 / `jsonl` | 非技术观众看不懂；没有"动作"，谈不上视觉说服力 |
| 用商业脑控游戏/Unity Demo | 依赖专有 SDK 与美术资源，超出**￥0 + 10 周**边界；`LSL4Unity` 许可证来源冲突（`NOASSERTION` vs MIT）**未定论**，采用前必须读 LICENSE 正文 |
| 只做"网页灯泡亮一下" | 无法承载分数/反馈/可重来，演示 30 秒就无话可说 |
| 等算法全做完再做游戏 | 违背 `MVP规格说明书` L35/L60 的判断——**F4 是最大缺口，必须与 F1 并行开工**；串行必然延期 |

## User Journey

### Discovery → First Use → Success

**1. Discovery（团队内部）**
从 `AGENTS.md` / `MEMORY.md` 与主 PRD 的 F4 条款知道：弹球是 10/27 的"脸面"，且**可以立刻开工**（不等算法）。

**2. First Use（键盘版，W8 = 10/20 目标）**
```
pip install pygame-ce websockets
python game\pong.py --input keyboard
```
窗口起来，方向键控制挡板，接住球得分、漏球失分，能重开。**此步骤不需要解码器、不需要脑电、不需要模型。**

**3. Success（解码版，W9 = 10/27 前）**
```
python -m bci_decoder.cli run --config configs/demo_online.yaml --outputs websocket
python game\pong.py --input ws
```
- 想象左手 → 挡板左移；想象右手 → 挡板右移；
- **不动 → 挡板不动**（`idle`），角标安静显示 `IDLE`；
- 得分上涨、状态显示 `RUNNING`、角落显示最近一条消息的 `label` 与 `confidence`。

**4. 失败与恢复（同样属于正常旅程）**
- 解码器没起来 / 中途被杀：游戏**不崩溃、不退出**，显示"等待解码器"，恢复后自动续上（F5.3）；
- 模型未训练：恒 `idle`，挡板静止 —— **这是安全态，不是错误态**。

## MVP Features

### Must Have for Launch

> 逐条对齐 `MVP规格说明书` §3.1（F4.1–F4.4、F5.3）与 §6.1（A7、A8）。

#### 1. F4.1 弹球玩法完整（键盘控制）

**What:** 一个单窗口桌面弹球：球、挡板、得分、命中/漏球反馈、可重来。键盘方向键驱动，**完全独立于解码链路**。

**User Story:** 作为演示者，我想先确认"游戏本身是好的"——这样后面出问题时我能立刻判断是游戏坏了还是解码坏了。

**Success Criteria:**
- 键盘版现场可玩（A8 前半）；
- **有分数、有反馈、可重来**三件事齐全（缺一即不算完成）；
- 玩法为 **2 Hz 控制率**设计（挡板平滑插值移动，不要求高频输入）。

**Priority:** P0 ｜ **归属**: 黄凯森

#### 2. F4.2 解码消息替换键盘输入

**What:** 输入源从键盘换成**解码结果消息**（WebSocket 首选 `ws://127.0.0.1:8765`，`jsonl` 轮询为降级），驱动同一套玩法与渲染，只换 `input_source`。

**User Story:** 作为演示者，我想要同一个小游戏只换一个参数就变成脑控版——这样"键盘版先行"不是额外工作，而是同一程序的一个模式。

**Success Criteria:**
- **A7：游戏实际订阅到消息并驱动画面**（判据是画面随 `label` 改变，**不是"端口能连"**），证据 = 联调录屏；
- 测试口径：**动作与 `label` 一致**（`MVP规格说明书` §6.3）；
- 冻结字段**不得增删**：`t_data / t_wall / label / label_id / confidence / probs / state / compute_ms / window_seconds`；`label_id == -1` ⟺ `label == "idle"`。

**Priority:** P0 ｜ **依赖:** F5.1（WebSocket 输出打通）｜ **归属**: 黄凯森

#### 3. F4.3 `idle` → 挡板不动；`confidence` → 可调节手感

**What:** 把"没在想象/不可信"表现为**静止**；把置信度用于**手感**（高置信更果断），而不是用来制造动作。

**边界（本文明确化，避免踩坑）:** `confidence` **仅在 `label ∈ {left, right}` 时参与调速**；`label == "idle"` 时挡板速度**恒为 0**，**不得使用 `confidence` 参与移动**。

**User Story:** 作为演示者，我想要"我不动它就真不动"——这是整套 Demo 可信度的地基；一旦静止时挡板自己乱动，观众会立刻判定"这是假的"。

**Success Criteria:**
- 演示时**故意不做想象 → 挡板必须静止**（录屏/截图为证）；
- `confidence` 只影响速度/插值，**不改变方向语义**；
- 调参不需要改代码（`config_game.yaml` 或命令行）。

**Priority:** P1 ｜ **来源:** `TechDesign-Game-MVP.md` §6 语义约束

#### 4. F4.4 演示界面显示当前 `label` 与 `confidence`

**What:** 界面上显示得分、运行状态、挡板位置，以及**最近一条消息**（角落或标题栏）。

**User Story:** 作为演示者，我想要观众能自己看见"系统认为我在想什么、它有多确定"——这样我就不用替系统说话。

**Success Criteria:**
- 投影/截图下可见，关键数字 **≥ 24 px**；
- **绝不显示任何"准确率"**（红线：MVP 阶段不对外报告任何准确率数字）；
- 未训练/不可信时安静显示 `IDLE`，**不弹错误框、不刷红字**。

**Priority:** P1

#### 5. F5.3（游戏侧承接）断线重连不崩溃

**What:** 解码器未启动、中途被杀、消息畸形时，游戏保持运行并自动恢复。

**User Story:** 作为演示者，我宁愿看到"等待解码器"的一行小字，也不愿看到程序退出、要重新演示一遍。

**Success Criteria:** 杀掉解码进程后游戏**不退出**；解码器回来后**无需重启游戏**即可继续驱动画面；未知 `cmd` / 畸形消息**忽略并记日志**，绝不崩溃。

**Priority:** P1

## Out of Scope (Not in MVP)

**明确不做，且不得挤占 F1–F5 的时间**（`MVP规格说明书` §2.2、§11.3）：

- **Unity / 3D / 手机端 / 网页版** —— 属"企业未来客户端"分支，待企业确认后再评估；
- **联机、排行榜、多人对战**；
- **商业化美术、音乐、关卡设计**；
- **任何形式的准确率展示**（红线：MVP 阶段不对外报告准确率）；
- **物理引擎 / GUI 框架（Qt、Tk）/ Node 与构建工具**（明确排除，避免无谓依赖）；
- **高帧率竞技手感、快节奏连击**（2 Hz 控制率下无意义且必然抽搐）；
- **训练模型、判定"想象左手还是右手"**（游戏端是**消费者**，它不需要懂脑电）；
- **脑电采集、滤波、特征、分类**（解码侧职责）；
- **LSL 真实设备接入、校准流程、黎曼几何/欧氏对齐、深度学习模型、4 类运动想象**（里程碑 ④ / 本期不做）；
- **Docker / 一键部署、跨平台打包**（里程碑 ⑥；MVP 为 Windows 单机）；
- **脑控轮椅实物与采集硬件**（不做）。

## Look & Feel

**Design Vibe:** **干净 · 跟手 · 可复现 · 诚实**（2026-10-15 团队确认，不替换）

| 视觉原则 | 游戏端的具体落法 |
|---|---|
| 1. **跟手优先**：让画面抽搐的实现都不算"完成" | 60 FPS 稳定；指令到达瞬间开始插值；**宁可不动，也不乱动** |
| 2. **诚实不装**：不显示没有依据的数字 | 显示真实 `confidence`；**绝不显示任何"准确率"** |
| 3. **一眼看懂**：投影仪上后排也看得清 | 大字号得分、高对比配色、深色背景、边框明确；关键数字 ≥ 24 px |
| 4. **失败也是安全态**：模型缺失时界面安静地不动 | 恒 `idle` → 挡板静止 + 角标 `IDLE`，不弹错误框、不刷红字 |

**界面元素（必须有）:** 得分、运行状态、挡板位置、**最近一条消息**（角落或标题栏）。

**Key Screens:** 只有一个窗口——游戏主画面（无菜单、无设置页、无启动页）。**能少一层就少一层**，因为演示现场没有时间点菜单。

## Technical Considerations

| 维度 | 结论 |
|---|---|
| **Platform** | Windows 普通笔记本**单机桌面窗口**（无独立显卡），与解码器**同机**运行 |
| **Chosen stack** | **已定**：Python 3.14.7（`bci-decoder/.venv`）+ **`pygame-ce`**（渲染/主循环，import 名 `pygame`，2026-10-16 实测装通）+ **websockets**（asyncio 客户端，17.2，已端到端验证）+ PyYAML（可选配置）。依据 `MVP规格说明书` 附录A 与学习路线图，**非"待定"** |
| **输入源可切换** | `--input keyboard｜ws｜jsonl`，三者实现同一接口，**共用同一套玩法与渲染**；降级不改玩法代码 |
| **Responsive** | 窗口尺寸适配演示机/投影；**具体分辨率与缩放待定（见 Open Questions）** |
| **Performance** | 主循环 60 FPS；控制率 **2 条/秒**（窗口 2.0 s / 步长 0.5 s，**冻结不得改**）；指令到达即开始插值；游戏端不得成为延迟瓶颈 |
| **Accessibility** | 关键数字 ≥ 24 px；高对比、深色底；`idle` 有文字角标而非仅靠颜色区分 |
| **Security / Privacy** | 只连**本地回环** `ws://127.0.0.1:8765`；**不上传任何数据、不联网**；不采集真人患者数据（伦理未走完） |
| **Scalability** | 不适用（单机 Demo）。真正的可扩展点在"可替换消费者"架构：游戏坏了不影响链路成立（`console` / `jsonl` 照样验收） |
| **测试** | `ws_client` 不依赖 Pygame，可单独单测（喂样例 JSON，**不依赖真连接**） |

## AI / Automation Scope

**Product AI: none。** 游戏端是**确定性消费者**：收到 JSON → 查表 → 移动挡板。产品内**不使用任何 AI / LLM / 模型推理**。

**Automation in product:** 无自动决策；唯一的"自动化"是断线重连与安全降级（`idle` → 静止）。

**AI 仅用于辅助开发**：由 AI 编码助手按 `AGENTS.md` 施工（vibe-coding 工作流 Part 4），人工负责跑测试、真机联调与现场验收。

## Quality Standards

- **单测**：`python -m pytest game\tests -q`（协议解析喂样例 JSON，不依赖真连接）；
- **人工验收 3 项**：键盘版可玩 / A7 联调录屏 / `idle` 静止；
- **健壮性红线**：未知 `cmd` 与畸形消息**忽略并记日志，绝不崩溃**；断线不退出；
- **诚实红线**：**不显示、不宣称任何准确率**；`mock`/`synth` 结果不当作成绩；
- **文档一致性**：线框图、字段表、命令在 `PRD-Game-MVP.md` / `TechDesign-Game-MVP.md` / `MVP规格说明书` 三处**必须一致**；
- **可复现**：4/4 成员各自机器上跑通同一套命令（"只有一个人会跑 = 没有人会跑"）。

## Budget & Constraints

**Budget:** **￥0** —— Pygame 与 websockets 均开源免费；无美术与外包成本；不引付费云服务、不用 conda 生态。

**Constraints（红线）:**
1. 控制率仅 **2 条/秒**（窗口 2.0 s / 步长 0.5 s，**冻结**）；
2. `idle` 必须表现为挡板**不动**，且 `idle` 时**不使用 `confidence`** 参与移动；
3. 输出字段**不得增删**；`label_id == -1` ⟺ `label == "idle"`；
4. 类别固定 **2 类（左手/右手）+ `idle`**；通道顺序等解码侧约束不得被游戏端"顺手重排"；
5. **不对外报告任何准确率数字**；
6. Windows **PowerShell 5.1**，命令**不要用 `&&`**；`bci-decoder/` 内命令用 `.venv\Scripts\python.exe`；
7. 时间：10 周（2026-10-13 → 2026-12-15），**MVP 硬节点 10/27 不可延**；
8. 不采集真人患者数据；游戏端不得联网上传。
