## 0. 与当前交付物最相关：你们只需要先看这 5 个

你们的交付物是「**一段可被游戏调用的在线解码模块**」（输入 EEG 流 → 输出 label/confidence/probs/timestamp）。
围绕这条链路，优先级最高的 5 个仓库：

| 优先级 | 项目 | 为什么对你们最重要 |
|---|---|---|
| ★★★★★ | [`mne-tools/mne-lsl`](https://github.com/mne-tools/mne-lsl) | 官方推荐的**在线 EEG 采集 + 实时流**方案，基于 LSL。你们的 `sources/lsl.py` 接真设备时直接参考它的 StreamLSL / 实时缓冲写法。**先看这个。** |
| ★★★★★ | [`NeuroTechX/EEG-ExPy`](https://github.com/NeuroTechX/EEG-ExPy) | 一个**完整的实时 BCI 应用框架**：采集→处理→分类→反馈。它的架构分层（Stream / Transform / Classifier / Feedback）几乎就是你们 `bci_decoder/` 骨架的成熟版，抄它的设计哲学。 |
| ★★★★☆ | [`NeuroTechX/moabb`](https://github.com/NeuroTechX/moabb) | **离线基线评测的标准工具**。接 BCI IV 2a/2b、OpenBMI 数据做真实准确率评估，做跨被试实验，就用它。**禁止再用 mock/synth 数据对外报准确率。** |
| ★★★★☆ | [`pyRiemann/pyRiemann`](https://github.com/pyRiemann/pyRiemann) | **黎曼几何解码**，运动想象里公认的强基线（常超过普通 CSP+LDA）。你们规划里的「黎曼 + 欧氏对齐」路线，实现直接用它，不用自己写。 |
| ★★★★☆ | [`braindecode/braindecode`](https://github.com/braindecode/braindecode) | 基于 PyTorch 的**深度学习 EEG 工具箱**（EEGNet、Deep4Net 等）。当你们想把 LDA 升级成深度模型时的首选。 |

**关于游戏对接**：如果最终由企业/其他团队做游戏端，他们大概率用 Unity。
→ 见 [`labstreaminglayer/LSL4Unity`](https://github.com/labstreaminglayer/LSL4Unity)（第 3 节），这是 **Unity 接收 LSL 流**的标准方案，你们的黑盒模块只要按 LSL 或 WebSocket 输出即可被它消费。

## 5. 传统 BCI 平台（非 GitHub 为主，按需了解）

这些是有历史的成熟 BCI 平台，工程理念值得借鉴，但**不建议作为你们在线模块的直接依赖**（偏重配置/图形界面，嵌入现代 Python 流水线不便）：

- **BCI2000**（https://www.bci2000.org）—— 老牌实时 BCI 平台，信号处理/反馈模块化设计经典。
- **OpenViBE**（http://openvibe.inria.fr）—— 法国 INRIA 的可视化 BCI 开发环境，图形化搭建实时流水线。
- **EEGLAB**（https://sccn.ucsd.edu/eeglab/）—— MATLAB 离线 EEG 分析元老，多数数据集/教程以其格式为准。

建议：**了解其模块划分思想即可，动手仍用 Python 生态（mne-lsl / EEG-ExPy / moabb）**。

## 6. 建议阅读/上手顺序（对应你们里程碑）

对应 `docs/在线解码模块设计说明.md` 中的 M1–M6：

1. **M1 打通链路** → 读 `mne-lsl` + `EEG-ExPy`，确认你们的 `sources/lsl.py` 与 `outputs/` 设计是否对齐业界做法。
2. **M2 离线基线** → 用 `moabb` 拉 BCI IV 2a，配 `pyRiemann` 或 sklearn CSP+LDA，得到**真实**准确率（替代 mock 数据）。
3. **M3 在线化** → 参考 `EEG-ExPy` / `timeflux` 的在线缓冲与状态管理，对照修正你们 `pipeline/preprocess.py` 的因果滤波实现。
4. **M4 模型升级（可选）** → `braindecode` / `EEGNet` / `FBCNet` / `ATCNet`，先做离线对比再上线。
5. **M5 游戏联调** → 与游戏端约定 LSL 或 WebSocket 协议，Unity 端用 `LSL4Unity` 对接。
6. **M6 康复/产品化** → 参考 `BrainFlow` 设备抽象，兼容更多硬件。

---

## 7. 使用注意（避坑）

- **评测纪律**：`mock`/`synth` 数据只用于工程自检（链路是否通），**绝不能**用其交叉验证结果对外报准确率。真实评测必须走 `moabb` + 公开数据集。
- **在线 vs 离线**：`mne-lsl` / `EEG-ExPy` 里的滤波都是在线的（因果），不要照抄离线教程里的 `filtfilt`（会用到未来样本，在线不可用）。
- **通道顺序**：接真设备时通道顺序必须与采集设备一致，否则 C3/C4 侧向颠倒，输出会呈现相反结论。
- **许可**：商用前逐个确认 License（GPL 系项目若静态链接进产品会有限制；`mne-lsl`、`moabb`、`pyRiemann`、`braindecode` 多为 BSD/MIT 系，商用友好）。
