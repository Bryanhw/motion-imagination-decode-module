## 一、链路一页图（口播时指图讲）

```
电极采集 (8 通道, C3 Cz C4 CP3 CP4 P3 P4 Oz, 250Hz)
   │
   ▼ 滤波①：50Hz 陷波（去市电）
   ▼ 滤波②：8–30Hz 带通（留脑电有用频段）── 注意：在线用因果滤波
   ▼ 滤波③：CAR 共平均参考（去全脑共模）
   ▼ 切窗：2.0 秒窗、0.5 秒步长（每 0.5 秒出一个判断）
   ▼ 特征：CSP 空间滤波 + log-方差
   ▼ 分类：标准化 + LDA（输出左右后验概率）
   ▼ 稳定化三道闸：EMA → 连续 3 次一致 → 置信度≥0.6；未稳定保持上次，低置信退回 idle
   ▼ 消息：固定字段 JSON ──► 游戏
```

## 二、分段口播（讲什么 → 为什么 → 被追问的一句话）

### 第 1 段｜为什么是"8 个电极、放在运动区"

- **讲什么**：我们只用 8 通道，固定位置：`C3, Cz, C4, CP3, CP4, P3, P4, Oz`。
- **为什么**：想左手/想右手时，大脑**对侧运动皮层**活动会变化（ERD：mu/beta 节律功率下降）。C3/C4 正好盖住左右手运动区，CP/P 排是相邻的辅助位，Oz 在枕区当参考锚。**通道位置直接决定能不能读到意图**。而且这 8 个通道顺序是冻结的契约：CSP 的空间滤波器是按"通道顺序"训练出来的，顺序一换，输出就会错乱。
- **被追问**：为什么不用 64 导脑电更准？——通道多能拿到更多信息，但演示要普惠、要能换到常用设备；8 导是"够用 + 可落地"的平衡点。（如需展开，见 M3 §2："22 通道评测 与 8 通道工程演示 是两条分开的口径"。）

### 第 2 段｜为什么先滤掉 50Hz 和带通到 8–30Hz

- **讲什么**：50Hz 陷波 → 8–30Hz 带通 → CAR。
- **为什么**：
  - 50Hz 是国内市电频率，电极线像天线一样会拾进来，必须陷掉；
  - 运动想象的有效信号集中在 mu(8–12Hz) 和 beta(16–30Hz) 节律，带通把这些留下、把肌电/漂移等噪声砍掉；
  - CAR 是把全脑的共同背景（眨眼、全局漂移）减掉，突出"局部差异"。
- **被追问（红线必答）**：为什么在线不能用 `filtfilt`——因为零相位滤波要"看未来"，在线只能看过去。我们在线用**因果滤波 `sosfilt`，并且跨 chunk 传递内部状态 `zi`**。否则每 0.5 秒的一段数据从零状态重新滤波，块边界会出现跳变，解码就会乱跳。

### 第 3 段｜为什么 2 秒窗、0.5 秒步长

- **讲什么**：2.0 秒窗口攒够一段数据才算特征；每 0.5 秒滑动一次、出一个判断。
- **为什么**：脑电是随机波动，看一瞬间没有稳定规律。2 秒窗能拿到足够的节律周期（8Hz 信号在 2 秒里有 16 个周期），特征才稳；0.5 秒步长让游戏"每半秒收到一次指令"，兼顾反应速度和计算量。窗口/步长是项目冻结的契约（2.0s / 0.5s），匹配游戏节奏与验收口径。
- **被追问**：能不能更短窗口更"跟手"？——可以，但太短特征噪声大，误动作变多。2s/0.5s 是权衡后的数值。

### 第 4 段｜为什么用 CSP + LDA

- **讲什么**：特征用 CSP（共空间模式）空间滤波 + log-方差；分类用 LDA。
- **为什么**：
  - 单看一个电极看不出左右；CSP 是找一组"空间配方"（权向量 W），让左手信号在这配方下方差大、右手小（反之亦然），等于给两类各配一副放大镜；
  - 取出轮廓方向后，取 `log(var(z)/Σvar(z))` 作为特征，拉大两类距离；
  - LDA 在特征空间画一条最优分界线，输出后验概率——小样本、低延迟场景的强基线，在线只做一次矩阵乘，开销极小。
- **被追问**：为什么不能用更复杂的深度网络？——深度网络要海量标注数据，我们当前是个人校准、（每人）几十个 trial 的小样本场景，CSP+LDA 是"样本少也能学"的最稳选择。真实数据规模上来再谈深度学习。

### 第 5 段｜为什么"稳定化三道闸"必须有

- **讲什么**：分类器之后还有三道闸：EMA 平滑 → 连续 3 次一致 → 置信度 ≥0.6；未连续一致时**保持上一次输出**，连续一致但置信度不足才切到 `idle`。
- **为什么**：单次分类会抖，直接发动作游戏会乱跳。三道闸保证**只在有把握且稳定时才切换动作**，其余时候保持旧指令或给 `idle`（不发动作）。
- **被追问（红线必答）**：**未训练时为什么会是 idle？**——未训练时分类器输出均匀概率（0.5/0.5），置信度 0.5 < 0.6 门限，稳定化在链路设计上就强制输出 `idle`。这不是靠人守纪律，而是链路本身保证：**绝不给游戏发随机左右指令**。

### 第 6 段｜为什么输出"固定字段的 JSON"

- **讲什么**：最终输出一条冻结字段的 JSON 消息（`label / label_id / confidence / probs / state / compute_ms / window_seconds / t_data / t_wall`），游戏只认这套字段。
- **为什么**：**解码端和游戏端解耦**。模型、通道、滤波怎么改都不影响游戏——只要字段不变，游戏零改动。这就是"换模型不改游戏"的接口设计。`label_id == -1` 当且仅当 `label == "idle"`。
- **被追问**：加一个字段行不行？——不行，这是已冻结的对外契约，改动要走变更流程（见 MVP 规格说明书第 9 节）。

## 三、收尾：接个人校准叙事（D3）+ 分屏录屏

> （这一段直接接下段口播，展示 D3 一页纸内容：）
> "前面讲的是'同一套链路人人都能跑'。但有一个现实问题：**不同人的脑电指纹不一样**。拿别人的模型直接测新用户，Kappa ≈0.19，接近随机。让本人做 **约 4 分钟**想象任务校准（每类 20 trial）后，Kappa 到 **0.36**，过 0.3 达标线。"
> "还有人校准后也偏弱？——那是个体差异（文献里叫 BCI illiteracy）。所以我们产品设计了**试玩门**：能玩才交付，不稳就加数据，**不承诺任何真人数值**。"
> （切录屏）"校准完成后的个人模型回放，直接驱动我们的小游戏——左边游戏，右边解码器：实时波形、实时 JSON 决策日志、状态灯。这就是从'意图'到'指令'的完整闭环。"
