## 1. 一句话看懂整个骨架

```
脑电帽 ──▶ 【sources】造出/收到数据块 ──▶ 【preprocess】洗数据（带状态滤波）
                                                    │
                                                    ▼
                                            【buffer】环形缓冲（定长）
                                                    │
                                    每累积 step 个样本触发一次决策
                                                    ▼
                            取最近 window 个样本 ──▶ 【features】找特征
                                                    │
                                                    ▼
                                            【classifier】下判断
                                                    │
                                                    ▼

                                                    │
                                                    ▼
                        【outputs】console / jsonl / websocket ──▶ 游戏
```

**这条链路就是《项目计划书》2.1 那张图**。第 1 节那张"等 2 秒 → 洗数据 → 找特征 → 下判断 → 防抖动 → 输出"的流程图，

## 3. 看懂骨架必须先记住的 5 个约定

这五条是**全局约定**，不知道它们，读代码会处处困惑：

| # | 约定 | 在代码里的体现 |
|---|---|---|
| 1 | **数据的形状永远是 `(通道, 时间)`**，不是 `(时间, 通道)` | 8 通道 × 250 Hz，2 秒窗口 = `(8, 500)`；`axis=-1` 几乎总是时间轴 |
| 2 | **单位是微伏 µV**，不做量纲转换 | `mock.py` 里节律 15 µV、噪声 5 µV；伪迹阈值 200 µV |
| 3 | **通道顺序即语义**，顺序错了左右会稳定相反 | `config.py` 的 `DEFAULT_CH_NAMES = [C3, Cz, C4, CP3, CP4, P3, P4, Oz]` |
| 4 | **参数一律走 YAML → Config 对象**，代码里不写魔数 | `cfg.window_samples()` = 窗口秒数 × 采样率 |
| 5 | **滤波必须带状态、跨块连续** | `StreamFilter.state`（这条是 ⭐⭐⭐ 门槛，见第 5 节） |

## 4. `core.py` 精读：一次 `push()` 发生了什么

`core.py` 是骨架的心脏，只有 131 行。核心就是 `push()` 这一个方法（第 57–96 行）。
**它的执行顺序有讲究，请逐行对照：**

```python
def push(self, chunk):                                    # chunk: (8, 25) 一小块脑电
    clean_data, is_clean = self.pre.process(chunk.data)   # ① 先滤波（带状态，跨块连续）
    self.buffer.append(clean_data, chunk.t0)              # ② 再入环形缓冲

    outputs = []
    self._since_last += clean_data.shape[1]               # ③ 累加"距上次决策过了多少样本"

    while self.buffer.total >= self.window_samples and self._since_last >= self.step_samples:
        self._since_last -= self.step_samples             # ④ 够一个步长就触发一次决策
        t_start = time.perf_counter()                     # ⑤ 开始计时（只计计算，不计等数据）

        window = self.buffer.get_last(self.window_samples)  # ⑥ 取最近 2 秒 = (8, 500)
        feat   = self.features.transform(window)            # ⑦ 找特征 → 4 维向量（CSP log-方差）
        probs  = self.classifier.predict_proba(feat)        # ⑧ 下判断 → [P(左), P(右)]
        label, conf = self.stabilizer.update(probs, self.class_names)  # ⑨ 防抖动

        compute_ms = (time.perf_counter() - t_start) * 1000.0  # ⑩ 算这次花了多久
        ...
        outputs.append(DecoderOutput(...))                # ⑪ 组装成一个消息
    return outputs
```

**五个必须理解的点：**

1. **顺序是「先滤波，再入缓冲」**（①②）。所以缓冲里存的**已经是洗过的数据**。
   这意味着：滑窗取出来的 2 秒数据，是**已经带状态滤过的连续数据**——这正是实验 B 要保证的性质。

2. **触发条件是 `while` 不是 `if`**（第 65 行）。一个 25 点的块在步长也是 25 点时正好触发一次；
   但如果步长比块小，**一个块可能触发多次决策**。这个 `while` 就是为此写的。

3. **`compute_ms` 只量计算，不包含等数据的时间**（⑤⑩）。这是全项目最重要的度量区分：
   `compute_ms` ≈ 1–2 ms，而端到端 ≈ 2000 ms。**瓶颈在窗口，不在算法。**
   对应验收 A4（p95 < 50 ms）和 A5（延迟可解释）。

4. **`is_clean` 只影响 `state` 字段，不改变 `label`**（第 79–81 行）。
   伪迹超标时输出 `state="stabilizing"`，让**游戏侧**自己决定放缓动作，而不是模块单方面丢数据。
   这对应 MVP 规格 F1.5「伪迹**只标记不丢弃**」。

5. **`latency_report()` 直接把两段时间加在一起**（第 130 行）：
   `est_e2e_p95_ms = p95(compute) + window_seconds * 1000`。
   这就是演示第 3 页那个"99.9% 在等数据"的分解，**是 `cli benchmark` 输出的核心数字**。

## 5. `preprocess.py` 精读：⭐⭐⭐ 门槛所在

这是全骨架**唯一需要"懂信号"才能看懂**的文件，也是决定"回放准确率与离线差 < 5%"成败的地方。

### 5.1 `StreamFilter` —— 就这么短，但它是关键

```python
class StreamFilter:
    def __init__(self, sos, n_channels):
        self.sos = np.asarray(sos, dtype=np.float64)
        # scipy 约定：多通道 (n_ch, n_t) + axis=-1 时，zi 形状为 (n_sections, n_ch, 2)
        self.state = np.zeros((self.sos.shape[0], int(n_channels), 2), dtype=np.float64)

    def process(self, x):
        y, self.state = sosfilt(self.sos, x, axis=-1, zi=self.state)   # ★ 传进去、存回来
        return y
```

**核心只有一行**：`sosfilt(..., zi=self.state)` 把状态传进去，再把返回的新状态**存回 `self.state`**。
就是这一行，让"分块流式"等价于"一次性滤波"。

**跑一下 `docs/learning/causal_filter_lab.py` 的实验 C**，你会看到不传状态的后果：
不是"精度差一点"，而是**每个块边界一次阶跃**（最大一阶跳变放大 2.4 倍）。
而阶跃会污染窗口内的特征（无论频带功率还是 CSP log-方差）→ 特征抖动 → 输出乱跳。**而且它不会报错。**

> **🔍 骨架里已经有 T3 的雏形，别白写一遍**
>
> `bci-decoder/tests/test_pipeline.py` 第 22–25 行（用例
> `test_preprocessor_shape_and_streaming_state`）做的就是这件事：
> 分块处理两次，与一次性处理整段比较，`atol=1e-8`。
>
> 我**实测验证过它有效**（不是假测试）：正确实现误差 `0.000e+00` → 通过；
> 把状态传递去掉后误差 `6.821e-01` → 失败。
>
> 但它有四个缺口，**这才是你们要补的活**：① 只测了一种块长（25 点）；
> ② 没有覆盖 T4"块边界无跳变"；③ 没有覆盖 `reset()` 行为（④ 阶段切被试要用）；
> ④ 用的是 3 通道，而项目冻结值是 8 通道。
>
> **完整参考实现见 `docs/learning/test_t3_t4_reference.py`**（12 项，全部通过）。
> 但请**先自己写**，卡住了再对照——`写不出 → 看答案 → 自己重写` 才有用。

### 5.2 滤波器设计：两个函数，各一行

```python
def design_bandpass(sfreq, l_freq, h_freq, order=4):
    return butter(order, [l_freq, h_freq], btype="bandpass", fs=sfreq, output="sos")

def design_notch(sfreq, f0, q=30.0):
    b, a = iirnotch(f0, q, fs=sfreq)
    return tf2sos(b, a)          # 统一转成 SOS 形式，便于级联与带状态处理
```

- **`output="sos"`**：二阶节（Second-Order Sections）级联形式。数值上比 `(b, a)` 稳定得多，
  **在线滤波应该优先用 SOS**——这是个可以直接写进报告的好习惯。
- **为什么先陷波（50 Hz）再带通（8–30 Hz）**：50 Hz 早已在 8–30 Hz 之外，带通本来就能滤掉它。
  先陷波是**工程保险**：万一工频很强，先压掉能避免带通级的中间结果饱和。

### 5.3 处理链的顺序（`process` 方法，第 58–74 行）

```
notch(50Hz 因果) ─▶ bandpass(8–30Hz 因果) ─▶ CAR 重参考 ─▶ 峰峰值伪迹标记
```

- **CAR（共平均参考）**：`y = y - y.mean(axis=0, keepdims=True)`。
  **`axis=0` 是通道轴**——对每个时间点，减去该时刻所有通道的均值。
  这一步能去掉所有通道共有的干扰（参考电极噪声等），无状态、零成本。
  ⚠️ **常见错法**：写成 `axis=1`，那就变成"每个通道减自己的均值"，把慢漂移去掉了、把 CAR 完全做错了，
  **而且不会报错**。实测（8 通道合成数据）：正确写法各通道均值是 `[-6.89, -5.04, ..., 6.96]`，
  错误写法是 `[0, 0, ..., 0]`（因为"减自己的均值"必然归零），**两者最大差异 21.7 µV**。
  > **注意区分**：`y.mean(axis=...)` 写错是**静默错误**；
  > 而 `sosfilt(..., axis=...)` 写错会**立刻抛 `ValueError: Invalid zi shape`**——
  > 属于"响亮的错误"。真正危险的是前者，以及下面第 5.1 节那种不报错的。
- **伪迹检测用峰峰值**：`ptp = np.ptp(y, axis=1)`，超阈值就 `clean=False`。
  **只标记不丢弃**（对应 F1.5）——丢弃会造成输出中断，游戏体验更差。

### 5.4 ⚠️ `preprocess.py` 文件头那句话（第 3–5 行）

> 与离线处理最大的区别：**必须使用因果滤波器并保持跨 chunk 的滤波状态**，
> 否则每个 chunk 边界都会产生跳变，导致特征抖动、在线表现远差于离线。

**这句话就是本项目的核心技术风险，写在了源码第一段。**
它对应《项目章程》风险登记表里那两条："因果滤波与离线不一致 → 在线无效"、"从第一天就用因果滤波；`replay` 回放必测"。

## 6. 另外三个"为什么这么设计"

### 6.1 `buffer.py`：为什么不用普通 list？

> 实时系统里数据会无限增长，必须用固定容量缓冲。（源码注释第 3–4 行）

- 容量 = `window_samples * 4 + sfreq`（`core.py` 第 44 行）≈ 8 秒数据，**恒定不变**。
- `_total` **单调递增**，即使数据被覆盖也不回退 —— 这样才能用 `total % capacity` 算出写入位置。
- `get_last(n)` 用取模索引 `np.arange(start, total) % capacity` 取出环上的最近 n 个点，**返回副本**。

**这就是"连续跑 1 小时内存不增长"（验收 A10）的实现方式。** 用 list 会一直涨内存。

### 6.2 `postprocess.py`：为什么"宁可迟钝，不可抖动"？

```python
self._ema = a * probs + (1 - a) * self._ema     # ① EMA 平滑，抑制单次抖动
self._votes.append(top)                          # ② 连续 3 次一致才允许切换
if conf < self.cfg.min_confidence:               # ③ 不够自信 → idle
    self._current = self.idle_label
```

三层防护，各自解决一个问题：

| 层 | 解决什么 | 反面后果 |
|---|---|---|
| EMA 平滑 | 单次分类概率的随机抖动 | 挡板左右乱颤 |
| 3 次一致性投票 | 短时误判 | 方向频繁翻转 |
| 置信度门限 | "什么都不想时乱动" | 用户失去控制感 |

注意 **`_current` 的保持逻辑**（第 49–51 行）：不够稳定时**保持上一次输出**，而不是输出 `idle`。
这是刻意的：频繁切到 `idle` 会让游戏一顿一顿的。

### 6.3 `classifier.py`：`UntrainedClassifier` 为什么存在？

```python
class UntrainedClassifier(BaseClassifier):
    """占位分类器：输出均匀概率。
    作用：让整条在线链路在模型尚未训练时也能跑通，便于先验证工程链路。"""
    def predict_proba(self, x):
        return np.ones(self.n_classes) / self.n_classes
```

**这就是 MVP 阶段的"先通链路，再谈准确率"策略的代码体现**：
均匀概率 → 置信度 0.5 → 低于门限 0.6 → 恒输出 `idle`。
**未训练时恒 `idle`** 是《MVP 规格说明书》的红线 R-2（绝不让游戏乱动）。

### ⚠️ 第 5 条为什么最要紧

`pipeline/features.py` 的兄弟文件 `config.py` 里，`Config.from_dict()` 是这样过滤字段的：

```python
def sub(tp, key):
    data = raw.get(key) or {}
    valid = {f.name for f in dataclasses.fields(tp)}      # 只保留 dataclass 认识的字段
    return tp(**{k: v for k, v in data.items() if k in valid})
```

`WindowConfig` 的字段名是 **`window_seconds`** 和 **`step_seconds`**，
而《MVP 规格说明书》5.4 节的 YAML 片段写的是 **`seconds: 2.0`**（少了 `window_` 前缀）。

**后果**：如果谁"照着规格书粘贴配置"，这个 `seconds` 字段会被 `sub()` **静默丢掉**（不报错、不警告），
`window_seconds` 回落到默认值 2.0（这次凑巧一样），而 `step_seconds` 回落到 **0.25**——
于是**你以为是 0.5 秒步长，实际跑的是 0.25 秒**，刷新率悄悄翻倍。

> **这正是本项目反复出现的同一类错误：不报错，只给你一个错误的数字。**
> 同类错误：不传 `zi`、CAR 写成 `axis=1`、先标准化再切分训练测试。
>
> **动手验证**（建议现在就做）：
> ```powershell
> python -m bci_decoder.cli show-config --config configs/default.yaml
> ```
> 看输出里 `window.window_seconds` 与 `window.step_seconds` 的真实生效值。
> 我刚跑过，是 `2.0` 和 `0.25` —— **与文档冻结的 0.5 不符**。

**处理建议**：在第 1 次例会上按章程 7.1 的规则决策——技术项由阎浩文提议、全队过。
需要定两件事：① 步长到底用 0.25 还是 0.5（改 YAML 还是改文档）；
② 要不要给 `Config.from_dict()` 加一个"未知字段告警"，防止以后再有配置被静默吞掉。
决策结果写进 `docs/evidence/`（**配置即证据**，章程 5.4）。

### 9.4 ★★ 假测试审计（本节是本导读最重要的方法论）

> **一个断言只有在"注入它应该防住的那个 bug 之后会失败"时，才是有价值的。**
> 一个永远通过的测试，等于没有测试。

我在写参考实现时，做了这次审计（脚本：`docs/learning/tool_audit_fake_tests.py`），
对每条断言注入它该防的 bug，看它是否失败。结果：

| 断言 | 正常时 | 注入 bug 后 | 判定 |
|---|---|---|---|
| A. T3 分块 == 整段 | 通过 | **失败** | 有效 |
| B. T4 块边界无跳变 | 通过 | **失败** | 有效 |
| C. `reset()` 清空状态 | 通过 | **失败** | 有效 |
| D. `state` 形状约定 | 通过 | **仍然通过** | ⚠️ **假测试** |

**D 为什么是假测试**：我构造了一个"状态永不累积、但形状/初始化/`reset` 全都正确"的实现。
D 只检查形状，所以完全抓不到它。**只有 A（行为等价性）能抓到。**

**由此得到的两条结论，请记住：**

1. **形状类断言天生抓不到行为类 bug。** 断言"维度对不对"很容易，
   断言"算法行为对不对"才有价值。**T3 那条『分块喂入 == 一次喂入』就是行为类断言**，
   所以它是本项目最有价值的一条测试——它同时覆盖了状态传递、处理链顺序、`axis` 语义三件事。

2. **"会报错的错误"和"不报错的错误"要分开对待**：
   - 改错 `sosfilt(axis=...)` → **立刻 `ValueError`**（响亮，容易发现）；
   - 不传 `zi` / 状态不累积 / CAR 写成 `axis=1` / 配置字段名写错 → **一声不响地算错**
     （危险，必须靠行为测试和"审计"来防）。

**你们的任务**：写完 T3/T4 测试后，**故意注入一个错误**（比如把 `zi=self.state` 改成不传），
确认你的测试**变红**。如果它还是绿的，说明你写了个假测试——**这一步不能省**。
