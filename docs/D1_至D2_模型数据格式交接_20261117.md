## 1. D1 的数据格式（证据口径，已冻结）

来源：`BNCI2014-001`（BCI Competition IV 2a），MOABB 加载（`m4_calibration.py` 同款）。

| 项 | 值 |
|---|---|
| 受试 | 1–9（9 人） |
| 类别 | 2 类：left_hand / right_hand |
| 通道 | **22 通道**（见下，注意通道名） |
| 采样率 | 250 Hz |
| 单位 | µV（MOABB 返回） |
| 场次划分 | `0train` = session1（**只做校准训练**）／`1test` = session2（**只做测试**） |
| 滑动窗口 | 2.0 s / 步 0.5 s，从 cue 后 250 采样点起（3 个窗口/trial） |
| 预处理 | notch50 → BP 8–30 Hz（4 阶）→ 空间 CAR，因果 sosfilt 带状态（与 M3 一致） |

**BCI IV 2a 的 22 通道（顺序即语义，不得重排）**：

```
Fz FC3 FC1 FCz FC2 FC4 C5 C3 C1 Cz C2 C4 C6 CP3 CP1 CPz CP2 CP4 P1 Pz P2 POz
```

⚠️ **关键事实：BCI IV 2a 没有 P3、P4、Oz**（冻结 8 通道契约 `C3,Cz,C4,CP3,CP4,P3,P4,Oz` 里只有前 5 个存在）。
详见 §4 的通道口径决策。

## 2. D1 的模型格式（证据口径，**不要**直接进 cli）

D1 主脚本 `bci-decoder/scripts/m4_calibration.py` 用 **sklearn Pipeline**：

```
Pipeline([CSP(n_components=4, log=True, reg=None), LDA(solver="lsqr", shrinkage="auto")])
```

- 输入：窗口样本 `(n_windows, 22, 500)`（500 = 2.0s × 250Hz）
- 输出：2 类标签（0=left_hand, 1=right_hand）
- 训练：个人校准 = 该受试 `0train` 前 N/类 trial（N=10/20/30）
- 产出：`matrix_csp.csv`（Kappa/acc 对比表）+ `gradient_csp.png`（梯度曲线）+ README 复现说明
  （`docs/evidence/M4_calibration_20261117/`）

**为什么不直接复用**：该管道是 sklearn 对象，与 `bci_decoder.cli` 的部署模型
（`CSPExtractor` + `LDAClassifier` + `OOD` + `Config.source.ch_names` 映射）**不是同一套接口**。
D1 的使命是「证据链数字」（表+图），不进在线部署。

## 3. D2 的部署格式（calibrate.py / replay 契约，照此接）

部署模型走既有 `docs/calibration_flow.md` §7 契约，两步：

### 3.1 数据准备（**已给：`bci-decoder/scripts/m4_prepare_replay.py`**）

把 BCI IV 2a 某受试某场次导出为 replay / calibrate 能吃的格式：

```powershell
$env:PYTHONPATH = "D:/校企合作项目/bci-decoder"
# 例子：S05 的 session2（测试场）导出连续流 + 标签
& ".deepworks/venv_m3/Scripts/python.exe" bci-decoder/scripts/m4_prepare_replay.py `
    --subject 5 --session 1test --out-dir <你的机器 artifacts/m4_replay>
```

产出（在各自机器 `artifacts/m4_replay/`，**不入库**）：

| 文件 | 格式 | 说明 |
|---|---|---|
| `S05_1test_22ch_250hz.npy` | `(22, n_t)` float32, µV | 回放连续流（144 trial 拼接 ≈577s） |
| `S05_1test_labels.npy` | `(n_trials,)` int{0,1} | 每 trial 标签，供校准/对拍 |
| `S05_1test_trials.csv` | trial 起点样本索引 | 任一对齐用 |

> 校准侧（session1）同样导出：`--session 0train`。本机 `artifacts/` 若被系统拦 Python 写入（RA1），
> 先导出到别处再移动，或直接在能写盘的机器上跑。

### 3.2 模型训练（部署版，`calibrate.py`）

```powershell
# 在 bci-decoder 目录下；需要 22 通道配置（ch_names 用 §1 的 22 通道清单，sfreq=250）
& ".deepworks/venv_m3/Scripts/python.exe" scripts/calibrate.py --subject-id s05 `
    --real-data artifacts/m4_replay/S05_0train_22ch_250hz.npy `
    --labels    artifacts/m4_replay/S05_0train_labels.npy --config <22ch.yaml>
```

产出 → `artifacts/users/s05/{classifier.joblib, csp.joblib, online.yaml, metadata.json}`，
`online.yaml` 即可被 `cli run` 加载（sinks 可切 websocket 8765 → platformer）。

> ⚠️ calibrate.py 的 `--real-data` 目前默认按 8 通道校验（`cfg.source.ch_names`）。
> 用 22 通道时需给一份 ch_names=22 的配置，并把 `--trial-seconds` 与 BCI IV 2a trial 时长对齐（默认 2.0s
> 与 D1 滑窗一致，够用）。这一步属于 D2 的 calibrate 适配，本说明只锁定数据与通道口径。

## 4. 通道口径决策（⚠️ 需组长/王释贤拍板，D2 开工前）

两个可用选项，**推荐 A**：

| 方案 | 说明 | 评价 |
|---|---|---|
| **A. 22 通道全集（推荐）** | replay/calibrate 都用 BCI IV 2a 全部 22 通道（ReplaySource 与 CSP 均支持任意通道数），与 D1 证据**同一数据口径**，信息无损 | 链路改动最小、口径最一致 |
| B. 冻结 8 通道契约 | 需要 C3,Cz,C4,CP3,CP4,**P3,P4,Oz**；BCI IV 2a **缺 P3/P4/Oz** → 只能用替代数据（如 EEGMMIDB，旧 demo `demo_game_eegmmidb.yaml` 已通） | 与本周 BCI IV 2a 主线数据不一致，仅在新设备/演示需要 8 通道语义时考虑 |

**建议**：D2 录屏目标 = 「校准后的模型 + 真实 EEG 回放 + 游戏被驱动」。用方案 A（22 通道）
视觉上完全成立，且与 D1 证据数字同口径，评审口径最干净。若组长坚持冻结 8 通道，那 D2 数据
要么改 EEGMMIDB（非本周主线），要么等新设备真采——请先拍板再动 D2。
