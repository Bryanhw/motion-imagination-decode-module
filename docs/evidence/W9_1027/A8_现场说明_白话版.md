## 两台电脑怎么连（本次采用）

| 电脑 | 运行什么 | 先后 |
|---|---|---|
| **这台电脑** | 键盘版游戏；之后关闭键盘版，再开 `--mode ws` 游戏 | 先键盘，后接收数据 |
| **另一台电脑** | 合成信号解码器，向局域网 8765 端口发送决策 | 键盘版结束后，先于 WS 游戏启动 |

两台电脑连同一个局域网。**另一台电脑**安装演示包并运行包内 `setup.ps1`；在那台电脑的 `bci-decoder` 目录复制 `configs\demo_game_ws.yaml` 为临时配置，将 `output.ws_host` 从 `127.0.0.1` 改为 `0.0.0.0`，只供现场局域网演示，结束后不用提交。用 `ipconfig` 查它的局域网 IPv4 地址，记作 `<解码电脑IP>`；确认防火墙允许该机的 TCP 8765 入站。两机联动详情见正式手册 §1.6。

## 1. 上场前准备

1. 指定一台演示电脑，打开 PowerShell。现在这台电脑用下面三行；之后每开一个 PowerShell 窗口都要执行一次：

   ```powershell
   $Project = 'D:\CST AI\脑电运动想象\_ws_reconnect\bci-decoder'
   $Py = 'D:\CST AI\脑电运动想象\motion-imagery-eeg\.venv\Scripts\python.exe'
   Set-Location -LiteralPath $Project
   ```

2. 检查版本和模型。三项 `Test-Path` 都应输出 `True`；缺模型先运行下方生成命令。

   ```powershell
   git log -1 --oneline
   & $Py --version
   Test-Path artifacts\demo_csp.joblib, artifacts\demo_lda.joblib, artifacts\ood.joblib
   # 仅在模型缺失时执行：
   # & $Py scripts\bootstrap_demo.py --config configs\demo_online.yaml
   ```

3. 切到英文输入法。确认 8765 没被**旧解码器**占用：`Get-NetTCPConnection -LocalPort 8765 -State Listen -ErrorAction SilentlyContinue`。若有结果，先确认对应进程，再只关闭旧演示进程。**不要一键关闭所有 Python 进程**。本机 WebSocket 已明确直连 `127.0.0.1`，不必为演示关闭整个系统代理。
4. 打开录屏工具，确保 **PowerShell 解码器输出、游戏窗口和现场讲解声音**都录得到。开录后先口播：“现在是真人现场操作，第二段使用合成信号；不是真人脑控。”

## 2. 第一段：键盘试玩

在第一个 PowerShell 窗口执行：

```powershell
& $Py -m game.platformer.main --mode keyboard
```

点一下游戏窗口，按 **Enter** 开始；按住 **W** 前进，点按 **D** 向前跳。到达终点显示 `LEVEL CLEAR`，这是一关结束，**不是进入下一关**。到终点后可按 **R** 回到开始界面，再按 **Esc** 退出，确认 PowerShell 无异常栈。现场说：“这一段是键盘模拟，证明游戏能玩。”

勾选：前进 [ ]　跳跃 [ ]　到达终点 [ ]　正常退出 [ ]

## 3. 第二段：合成信号驱动游戏

**另一台电脑的 PowerShell**：进入它的演示包目录，设置 `$Py = '.\.venv\Scripts\python.exe'`，用临时局域网配置启动解码器。首次冷启动可能要十几秒；看到 `idle/left/right` 决策输出后再开这台电脑的游戏。

```powershell
& $Py -u -m bci_decoder.cli run --config configs\demo_game_ws_lan.yaml
```

正式录制要同时留决策日志时，可把这条换成：

```powershell
$Date = Get-Date -Format yyyyMMdd
$Log = "A8_解码决策log_$Date.txt"
& $Py -u -m bci_decoder.cli run --config configs\demo_game_ws_lan.yaml 2>&1 | Tee-Object -FilePath $Log
```

断线后再次运行时，在 `Tee-Object` 后加 `-Append`，保留前半段日志。

**这台电脑的 PowerShell**：按第 1 节设置 `$Project`、`$Py`，把命令里的 `<解码电脑IP>` 换成刚记录的真实 IPv4，再运行游戏。

```powershell
& $Py -m game.platformer.main --mode ws --ws-url 'ws://<解码电脑IP>:8765' --timeout 1.5
```

游戏里看 `WS CONNECTED`，点游戏窗口按 **Enter**。等待首个 2 秒数据窗产生判断。`left` 映射为**向前走**，`right` 映射为**跳跃**，`idle` 不发新的走/跳指令；跳跃中即使变成 `idle`，角色仍可能因已开始的跳跃惯性继续向前、自然落地。**不要讲成“左右走”或“idle 当帧绝对静止”**。不保证合成信号恰好通关或吃到全部金币，重点观察连接、状态切换和角色动作。

现场必须说：“现在用的是**合成演示信号**。它验证解码器消息能驱动游戏，**不是真人脑控，也不代表准确率**。”

勾选：连接 [ ]　向前/跳跃动作 [ ]　`idle` 无新增指令 [ ]　无异常退出 [ ]

## 4. 第三段：断线再连上

在**另一台电脑**的解码器窗口按 **Ctrl+C**。这台电脑的游戏应显示安全/重连状态，不再接收新的方向指令；若人物正在空中，先让它完成自然落地。然后在另一台电脑**重新执行第 3 节解码器命令**。客户端约每 0.5 秒尝试重连，实际连上时间还包括 Python 与模型的启动时间，**不能承诺“1 秒内连回来”**。看到 `WS CONNECTED` 和后续新决策才算成功。

勾选：断线不崩 [ ]　无新增指令 [ ]　重启后重连 [ ]　恢复接收决策 [ ]

## 换另一台电脑时

在源机的 `bci-decoder` 目录用 `scripts\pack_demo.ps1 -Zip` 生成演示包；目标机解压后运行包内 `setup.ps1`，并在目标机完成彩排。目标机的 `$Project` 改为解压目录，`$Py = Join-Path $Project '.venv\Scripts\python.exe'`。**不要复制源机的 `.venv`**；目标机模型和依赖必须按包内说明准备。环境快照也必须在实际演示的目标机采集。

## 出问题时

| 现象 | 先做什么 |
|---|---|
| Enter 能用，W/D 无反应 | 点击游戏窗口、切英文输入法；核对版本含桌面键盘修复 `6a5c414` 或更新提交。仍无反应就停下排查，不把失败段标通过。 |
| 按 D 崩溃 | 停止并记录报错，确认用的是含 `2165131` 修复的正式版；不要跳过 D 还宣称键盘段通过。 |
| 一直显示连接中 | 左边先等到解码器输出决策；查 8765 是否被旧进程占用，再核对游戏 `--ws-url`。 |
| 连上但人物暂时不动 | 看是否输出 `idle`、是否已按 Enter、角色是否已到终点；等下一次非 idle 决策。 |
| 重启后暂未重连 | 先等解码器完成冷启动、开始输出决策；再看游戏状态。 |

**现场结论模板**：“我们真人在场演示了键盘试玩、合成信号驱动、断线重连。这里证明的是工程链路与可玩性；真人脑电控制和算法准确率均不在本次演示范围内。”
