# 2c 缺陷 · OOD 低置信机制改进提案（任务书，供核心/组长评审）

> 日期：2026-10-20（D1）· 作者：阎浩文 · 状态：**提案/任务书**，待核心负责人评估后决定是否实施
> 结论先行：`demo_weak.yaml` 当前 40 决策仅 2 idle、38 right —— **OOD 高置信缺陷**，核心机制需补“域外检测”才能兜住“弱信号/来路不正 → idle”红线。

## 1. 缺陷复现与证据

- 配置：`bci-decoder/configs/demo_weak.yaml`（feature 提取沿用，弱/怪样本输入）
- 实测：40 决策分布 = idle 2 / right 38（复盘记录在 `myworkoutputs/T2_演示配置/`，D1 已降级交付并上报）
- 机制根因：CSP+LDA 对**训练分布之外的样本**（弱信号、噪声主导、增益漂移、伪通道干扰）仍会给出高置信 `left/right`；
  `postprocess.min_confidence=0.6` 只挡“两类都低”，挡不住“单类虚高”，因此门限失效。

## 2. 目标与验收（内部工程口径，不对外报准确率）

1. OOD/弱信号模拟集上 **idle 占比 ≥ 95%**（不再输出 right/left）；
2. 训练分布样本**不改差**：现有 22 项契约测试（`bci-decoder/tests`）全绿，且不破坏 17/17→22 既有口径；
3. 不触碰冻结项：窗口 2.0s / 步长 0.5s / 2 类+idle / 通道顺序与 9 字段契约一律不动。

## 3. 候选方案对比

| 方案 | 思路 | 对 OOD 高置信的兜底能力 | 成本/风险 |
|---|---|---|---|
| A. 概率校准（Platt/Isotonic） | 把 LDA 原始得分校准成更可信概率，再调门限 | ⚠️ 弱：校准主要拉平“置信 vs 正确率”曲线，未必能让 OOD 样本整体降置信；且需有监督校准集 | 低，但可能不解决问题 |
| **B. 域判别（推荐）** | 记住训练期 CSP 特征的“正常域”，用 OneClassSVM / 马氏距离 / 类中心距离 判断输入是否在域内，域外 → idle | ✅ 强：正面回答“这输入是不是训练域的东西”；与现有门限正交叠加 | 中：~50–100 行、需在特征层加一个离群检测器并标定阈值 |
| C. 特征在线监控 | 滑动统计特征能量/均值/方差，与基线悬殊 → idle | ✅ 中：对漂移型 OOD 有效 | 中：阈值依赖基线窗口，需标定 |
| D. 纯提高 min_confidence | 只会更难触发 | ❌ 无效（2c 的失败正是单类高置信） | 零 |

**推荐组合：B（域判别，主）+ A/C（辅助）+ 保留 D 现有门限做最后兜底。**

## 4. 建议实施路径（走 `MVP规格说明书` §9 变更流程，不擅自改动核心）

1. **先写文档提案**（本文件即提案 v0.1）→ 发群里请核心负责人/组长过目；
2. 若拍板实施：以“新机制开关（默认关/灰度开）”方式合入，落 `bci_decoder/pipeline/`（如 `ood.py`），
   并新增针对 OOD 模拟集的内部测试用例；
3. 用合成/synth 数据做**工程自检**（OOD 模拟集：高斯噪声、单通道增益×3、时域漂移伪样本等），
   **只做已达标证明，不写入对外报告**（红线 #5/#6）；
4. 回归：`bci-decoder/` 下 `python -m pytest`（22 项）+ 游戏端 39 项不回归（A 系列保持）。
