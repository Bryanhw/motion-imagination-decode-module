# 五分钟试跑基线与内存增长修复

王释贤本人首轮试跑：300.0035 秒、599287 个数据块、119857 条决策，正常结束。RSS 初始 117.8008 MiB，结束 123.3477 MiB，增加 5.546875 MiB；60 秒后仍由 119.52 增至 123.35 MiB。`修复前_5分钟/` 保存了原始日志、采样、配置、元数据和用户截图。

此结果证明试跑执行成功，**不判内存稳定通过**，也不替代一小时验收。

## 原因与修复

`DecoderEngine.compute_times_ms` 原为永久追加的列表，记录数与累计决策数相等，属于可确认的无界内存增长来源。改为最大 8192 条的有界 deque，淘汰最旧统计；缓冲、特征、分类、稳定化、九字段消息均未改变。

CLI 压测样本数未超过 8192 时仍统计全部样本；超过容量后 `n` 是保留样本数，报告另附 `n_total` 和 `sample_scope`。原来三轮 benchmark 每轮仅 120 条，原数据继续保留，不作回改。

长跑监测适配有界缓存：按累计输出数量计算新增决策数，分位数只使用该间隔可取得的最新样本，最多 8192 条；分别记录 `interval_outputs` 和 `interval_sample_count`，避免缓存填满后错误显示无新增输出。
