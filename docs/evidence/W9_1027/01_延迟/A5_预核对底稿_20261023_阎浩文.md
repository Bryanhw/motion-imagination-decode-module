## 2. 按 §4.3 补测（2026-10-24，脚本 `.deepworks/tmp/a5_stage_latency.py`）

实测条件：阎浩文开发机、无后台下载负载、`configs/demo_online.yaml`（2.0 s 窗 / 0.5 s 步 / vote3 / EMA 0.4 / OOD 开）。

| 段 | 指标 | 实测 | 说明 |
|---|---|---|---|
| ① 窗口齐备后计算 | P50 / P95 / MAX（n=120） | **0.67 / 0.91 / 8.99 ms** | 含预处理+特征+分类+OOD+稳定化；与 A4 存档 0.955 ms 吻合（10-23 的 1.19/2.27 系后台下载挤占） |
| ② 新类别确认等待 | 突变→稳定输出 | **1.5 s（3 步×0.5 s）** | 比组长估的 +1 s 更慢：EMA 拖尾先回 idle 再确认（序列 right→idle,idle,idle→left） |
| ③ 最后样本→输出 | ws 本地回环 P95 | **0.89 ms**（jsonl 0.04 ms） | 通信本身非瓶颈 |
| ④ 显示帧节拍 | 60 fps 最坏 1 帧 | **≈17.3 ms** | 游戏帧内 poll，典型 0~1 帧 |
| 合计 | **最后样本 → 显示** | **≈19 ms（P95）** | 0.91 + 0.89 + 17.3 |
| 合计 | **首次有效动作**（新类别出现→动作） | **≈3.5 s（最坏）** | 2.0 窗 + 1.5 确认 + 0.02 计算/传输/显示 |
| — | 真实「想象发生」时刻 | **不可测** | 无真人采集；不声称该口径 |

**结论修正**：
- 之前页面只报「起步 2.1 s」=**首个结果**（可能是 idle），**不等于首次有效动作**；按 §4.3 口径，**新类别→游戏动作最坏约 3.5 s**，已如实写入页面。
- 「端到端 <3 s」的说法**不成立于最坏情形**（3.5 s）；成立的是「稳态段每 0.5 s 一条指令 + 最后样本→显示 ≈19 ms」。
