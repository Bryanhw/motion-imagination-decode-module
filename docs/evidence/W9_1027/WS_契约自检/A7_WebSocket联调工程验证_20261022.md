# WebSocket 联调工程验证（2026-10-22）

> 本记录包含 A7 工程联调录屏的核验数据。视频使用合成 mock EEG，不是 A8 真人现场演示；没有评估分类准确率。

## 测试环境与数据

- 仓库提交基线：`4fc2356`（本次后续修复与数据归档另有提交）
- 数据：PhysioNet EEG Motor Movement/Imagery Dataset，subject 001 的 `S001R04.edf`。EDF 原件经 SHA256 比对后字节一致地归档；从 160 Hz 选择 8 个项目通道并重采样到 250 Hz，仅生成被 `.gitignore` 忽略的本地回放文件。
- 解码器输出：冻结的 9 字段 WebSocket 消息；游戏端适配器以本地接收序号映射消息。
- 演示分类器由 mock/synth 数据生成，不能用于这些 EDF 的分类性能结论。

## 结果

1. **真实 EDF → 解码器 → 游戏 WebSocket 客户端**：连接成功并收到合法决策（示例输出 `NONE`）。这验证真实 EDF 读取/预处理和消息传输，不验证分类是否正确。
2. **断线与重连**：停止解码器后客户端收到 `disconnected`；重启 mock 解码器后自动收到 `connected` 和后续消息。
3. **方向输入与游戏物理**：用 mock 的方向决策喂给 `DecisionReceiver` 和 `GameController`，收到 `LEFT_HAND` 并观察到角色 x 坐标从 28 增至 29.2。
4. **游戏窗口启动**：SDL dummy 环境下运行实际 `main(--mode ws)`，自动按 Enter 后正常退出，返回码 0。
5. **自动化测试**：解码器 `tests/` 31 项通过；平台游戏 + 其他游戏测试 32 项通过；`git diff --check` 通过。

## 修正

本机 Python WebSocket 客户端会自动读取 Windows 系统代理设置，导致 `127.0.0.1` 握手发给代理。游戏客户端和解码器 WebSocket 契约测试现在都明确传 `proxy=None` 直连本机；修复后真实本机 WebSocket 集成测试通过。

真人试跑又发现：pygame 普通 `KEYDOWN` 事件没有 `repeat` 属性，正式版主循环直接读取 `event.repeat`，按 D 会抛 `AttributeError` 并退出到 PowerShell。已在正式版和本机旧副本改为安全读取，并按键盘适配器已有状态抑制按住 D 的重复事件。新增真实 pygame 主循环回归检查，覆盖普通 D 事件、重复 D 事件与 `ws` 模式下的 D 键；正式版 63 项测试全部通过。**A7 录屏须使用修复后的正式版。**

## A7 联调录屏（修复版）

- 视频：[A7_联调录屏_ws.mp4](../A7_联调录屏_ws.mp4)；录制于 2026-10-22，使用 D 键修复提交 `2165131` 之后的正式平台游戏。
- 画面来自实际运行的 pygame 游戏窗口渲染面，视频底栏明确写明 `SYNTHETIC MOCK EEG - ENGINEERING TEST`。输入由真实运行的 `demo_game_ws.yaml` 解码器通过本机 WebSocket 发送。
- 约 21.7 秒、326 帧：启动后自动连接；停止解码器后出现断线并安全回到 `NONE`；重启后自动重连，角色继续受方向决策驱动。
- 录制时统计：连接 2 次、断线 1 次、决策 28 条；首次运行阶段有 183 帧方向输入，重启后收到 14 条决策。视频与统计仅证明链路和画面联动，不代表真人脑控或分类准确率。
