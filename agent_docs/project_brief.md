# 项目速览（project_brief）

> 给 AI 助手的"一页纸"上下文。目标是让你**在 1 分钟内知道这个项目在做什么、边界在哪、什么不能碰**。
> 深入内容见 `AGENTS.md`、`MEMORY.md`、`docs/`。

## 一句话

把脑电中的**运动想象意图**实时解码成**可被游戏直接调用的消息流**。

## 交付物是什么（注意：不是脑电算法，是模块）

```
[EEG 设备 / 文件回放] ──► [bci-decoder 模块] ──► [脑控游戏]
                              │
                              └─ 输出：一行一个 JSON（label / confidence / probs / 时间戳）
```

- **输入**：多通道 EEG 数据块（形状 `(n_channels, n_samples)`，单位 µV，250 Hz，8 通道）
- **输出**：消息流（`left` / `right` / `idle` + 置信度 + 概率 + 时间戳）
- **游戏端不需要懂脑电**——它只消费消息。

## MVP 要证明的三件事

1. **链路通** —— 数据进、决策出
2. **延迟可测** —— 有实测数字，并知道瓶颈在哪
3. **能演示** —— 现场跑得起来

**不证明准确率。** MVP 阶段不对外报任何准确率数字。

## 边界（不做什么）

- ❌ 不造采集硬件
- ❌ 不做医疗诊断级产品
- ❌ 不做 4 类运动想象
- ❌ 不做深度学习
- ❌ 不采集真实患者数据（伦理未走完）
- ❌ 不做脑控轮椅实物
- ❌ 不做游戏画面（那是游戏端的活）

## 最容易踩的四个坑

1. **在线用零相位滤波** → 在线表现远差于离线。必须 `sosfilt` + 跨 chunk 保状态。
2. **通道顺序被重排** → C3/C4 侧向颠倒，**稳定地输出相反结果**，极难排查。
3. **用合成数据显示"高准确率"** → `mock`/`synth` 交叉验证 100% 是必然结果，**不能当成绩**。
4. **以为算法是瓶颈** → 瓶颈是 2.0 s 窗口；换模型对端到端延迟毫无帮助。

## 关键数字

| 项 | 值 |
|---|---|
| 类别 | 2 类（左手/右手）+ `idle` |
| 滑窗 / 步长 | 2.0 s / 0.5 s |
| 采样率 / 通道 | 250 Hz / 8 通道 |
| 通道顺序 | `C3, Cz, C4, CP3, CP4, P3, P4, Oz` |
| 计算耗时 p95 上限 | **< 50 ms** |
| 端到端响应目标 | ≤ 3 s |
| 长跑 | 连续 1 h 无内存增长 |
